# Reusing a complete prepared duration order

Updated November 16, 2026. This is limited to explicitly enabled experimental
**Windowed Text** in chunked HTTP sidecar reports. It adds no controls, changes
no captured records and does not enable windowing by default. Regenerate older
reports to get the updated runtime; no new recording is required.

## 问题与行为

筛选可能已经完成全量匹配和耗时排序，但仍在等待新窗口的 HTML。此时切换 Events
会先更新旧窗口，再用相同完整命中集合重试筛选。此前只缓存已提交窗口的排列，
尚未提交的完整排序会随旧候选被放弃，再扫描并排序全部记录。混合示例的复现中，
一次筛选只匹配一次，却排序两次；这不是多次筛选条件导致的必要工作。

现在每个窗口渲染器额外保留最多一份**完整、结构校验通过、尚未提交的耗时排列**：

- 优先复用已提交窗口的排列，其次复用待提交排列。必须同时匹配不可变完整顺序
  plan 的**对象身份**和升/降序方向；仅内容相似、命中集合相同或任务相同不算命中。
- 完整排列与筛选、Events 显隐无关，因此仍应用最新的完整命中集合、折叠规则和
  显隐偏好。旧窗口的反向排序刷新不能挤掉待提交的另一方向排列。
- 同步及协作式排序使用同一缓存规则。缓存前校验完整条数、每个 ordinal 与原始
  行号的对应关系及唯一性；失败、被中断或取消后迟到的排序不能加入缓存。
- 行块加载失败不使完整有效的排列失效，Retry 可重新加载行。下一份新完成排列
  替换旧待提交排列；成功提交时直接移交所有权，不复制全量数组。销毁渲染器清空
  缓存，不能从旧报告或旧窗口渲染器继承。

之前的筛选事务语义保持不变：新窗口和导航在需要的行块通过校验后统一提交，
取消不发布部分结果，迟到响应不能覆盖新操作。完整 Text 回退、原始地址/参数、
源码与 Timeline 数据不变，挂载窗口仍最多 160 个展示单元。

## 成本与限制

这不是有界总内存方案。已提交排列之外，至多额外保留一份完整的行号数组及
`Uint32Array` ordinal 数组；新排序和候选几何还会有临时分配。结构校验另需短期
每条记录 1 字节的去重掩码，并进行一次全量扫描，不能说冷排序没有新增成本。
完整模型、重新投影、完整导航校验、HTML 读取和 DOM 解析仍需时间。

**只取消重复的已完成排序，不复用部分排序，也不跳过记录或缩小完整结果。**
方向或 plan 改变、上一份排列已被替换、首次排序或排序被中断时仍需计算。
完整 Text、默认非窗口 Text 和 Timeline 的排序逻辑没有改变。

## 验证

浏览器覆盖混合输入的同步排序、超过 16,384 条记录的协作式排序、Events 切换、
反向已提交排列、单项缓存替换、plan 身份、方向、渲染器销毁、行块失败重试，
以及缺失/重复/越界/错配 ordinal 等非法排列不能污染重试。已有取消、迟到完成、
Full Text 交接、任务/时间顺序、非有限耗时和源码配对回归继续验证。

本地复现、完整 Pi4 成对比较和日志位于 `build/windowed-prepared-ranking/`。
比较基线为 `fb6ace6c9840`，不是会丢失待应用筛选的旧版本；不能把取消的操作与
成功完成的操作比较成性能收益。两个变体只替换窗口运行时，共享同一份完整数据。

该 Pi4 输入是 53,711,530 字节、371,997 条记录、684 个事件，SHA-256 为
`b2375370c5bafba8de3bea2cf6bd8fff67e2435a71be2505a35cc9be72411ae7`。
筛选 `func:mutex sort:desc` 应保留全部 772 条命中；挂起首次行块读取后隐藏事件，
两版都应完成该筛选并保持完整导航排列、全部模型行字段和 Timeline 摘要一致。
这份输入没有提供源码二进制，不能外推到源码密集报告、移动设备或所有硬件。

完整 `test_textwindow`、`test_filter_matchers`、`test_report` 和 `test_sidecar`
共 184 项回归全部通过，无跳过。针对非法同步及协作式排列的重试也通过，不能
用一次成功缓存掩盖后续错误。异步夹具先完成数据预载，再同步安装交错操作的门控，
避免把预载与等待排序混成测试准备阶段的未决 Promise。

正式对照在 Chromium 145.0.7632.6、1440 × 900 下交替运行三组成对新上下文，
期间不并行测试、打包或 profiler。两版六次均保留 772 条命中、完整排序和全部
模型/Timeline 摘要，完整匹配均只执行一次，已完成排序调用次数由 **2 次变 1 次**。
94 份数据资源均硬链接到相同文件，并记录各自 SHA-256。
