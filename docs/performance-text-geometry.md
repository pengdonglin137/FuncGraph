# Text 重建热点 / Ordinals and fold visibility（2026-11-13）

优化的是**显式启用的实验性 Windowed Text** 的完整模型重建，而非只计算首屏。
无需新增参数；重新生成分块 sidecar 后，使用 Text 工具里的 **Windowed Text**，
或在 HTTP URL 后加 `?text=windowed`。默认完整 renderer、自动分流阈值、版本号、
Timeline 数据和外观均不改变。入口及限制见[窗口化说明](performance-text-window.md)。

## 热点与实现

这是 ordinal 阶段的实现与测量记录。后续无筛选路径改为复用现有范围生成按次
字节掩码；有筛选路径保留下文 predicate，见[折叠范围优化](performance-text-fold-visibility.md)。
这里保留原阶段的基线和数字，不跨阶段混比。

此前排序、可见序列与高度阶段反复按真实行号查找记录；已经缓存的完整排列仍未
携带对应原始 ordinal。每行还重新判断同一条祖先链是否被折叠，即使完全展开也
访问折叠字段。CPU profile 用于定位热点，**不作为正式耗时或加速比证据**。

- task plan 保存与完整原始行号排列逐项对应的 `Uint32Array` ordinal；time plan
  原序直接使用迭代位置，不分配数组。准备被取消时不发布半成品。
- 耗时排序连同 ordinal 排列，仅保留当前 plan/方向的一份排序缓存。改方向或
  模式时重算，退出耗时排序或销毁时释放；相同耗时仍遵循原稳定顺序。
- 排序和可见性直接读取 `model.records[ordinal]`；可见序列构造时同时写入真实行
  的已测/估算高度，以及合成边界的原有高度，不再按行号重复查找或单独遍历序列。
  typed array 保存的是**相对记录位置**，不是原始行号；大于 `2**40` 的稀疏 ID
  也不会截断。少量视口定位仍使用经 ID 核对的 point lookup。
- 每次同步 rebuild 新建可见性 predicate。没有严格 `=== true` 的折叠标志时
  不访问折叠字段；有折叠时先检查 filter/own-entry 规则，按完整祖先字符串缓存
  剩余可见性。重复祖先、缺失父项和特殊 ID 保留 reference 语义。
- fold-state 和 filter matches 在这次同步遍历中只读，不跨操作复用可见性结果；
  仅检测是否存在启用标志，不复制整份折叠状态。后一次折叠/筛选会重新计算。

没有删除原始行、参数或源码，也没有削弱完整 paint block 的逐行原文、属性及
源码配对校验。网络资源分组/LRU、512 行解析单位、160 单元挂载、取消与错误保留、
Full Text fallback 均不改变。普通完整 DOM 的逐行折叠 reference 路径不变。

## 内存与局限

task plan 增加 `4 × N` 字节，当前排序排列再增加 `4 × N` 字节；37 万行输入合计
为 **2,975,976 字节，约 2.84 MiB**。默认完整 renderer 复用同一个 task plan，
也承担第一项成本；不能声称默认路径零内存变化。仅使用 time 原序且未构建 task
plan/耗时排列时不分配这些数组；task plan 一旦构建仍随模型缓存，切回 time 不会
立即释放。退出耗时排序会清理当前排序缓存，不影响已缓存的 task plan。
冷排序的临时对象增加 ordinal 字段，按次祖先 Map 和 Object.keys 临时数组也另计；
已有模型、字符串、导航、高度、网络暂存不包含在上述数字中。

这不是总内存/峰值保证，也没有把同步全量 rebuild 改为分帧执行。大模型仍会阻塞，
分散 DOM 解析、GC 和等待资源仍可能主导就绪时间。只在本机 Chromium 验证，不能
外推为任意百万行、其他浏览器或源码丰富报告均已流畅。

### 回归范围

`tests/test_textmodel.py` 对比旧 reference，覆盖嵌套/重复/缺失祖先、严格 true、
特殊 ID、无过滤/空过滤、每次操作重新计算、共享 600 层祖先链、稀疏大行号、取消
后的完整 ordinal 排列及缓存复用。`tests/test_textwindow.py` 另对比 90 组顺序、
耗时方向、折叠和筛选组合的完整可见行/导航，限制 mounted ≤160，并防止同步重建
重新引入全量 point lookup；已有源码/取消/错误重试与 Full Text 用例继续执行。

```bash
python3 funcgraph.py TRACE --no-config --timeline --enable-fold --filter \
  --func-links --report-mode sidecar --output REPORT_DIRECTORY
PYTHONPATH=.:tests python3 tests/benchmark_text_rebuild.py BEFORE_DIR AFTER_DIR \
  --trace TRACE --rounds 3 --scattered --folded --output rebuild-benchmark.json
PYTHONPATH=.:tests python3 -m unittest -v test_textmodel test_textwindow
```

`--folded` 在筛选前加入 sparse、dense、unfold 及 warm 重建；sparse 取每 31 个真实
fold entry 的一个，最多 128 项，dense 启用全部真实 entry。设置状态后只调用一次
rebuild，不把逐项点击的多次隐式重建计入一次耗时。原始七步基准默认仍保持不变，
`--scattered` 继续插入排序窗口首/下一窗/返回访问。

打包校验归档于 `build/benchmarks/20261113-text-geometry/`，不自动上传。
