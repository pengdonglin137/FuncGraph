# Text 重建的临时分配与任务边界投影

完整/窗口 Text 共用的导航重排不再先为每行创建 `[line, index]` 数组；显式
**Windowed Text** 重建直接按已排序的原始位置消费任务边界，不再建立第二份
按行号索引的边界 Map，也不在每个可见行后重新分配空的 pending 数组。无需
新增参数，默认完整 DOM 加载策略和报告格式不变；本页只测量窗口模式交互，
不据此声称完整 Text 首开更快。

## 实现与准确性

- 导航重排先检查 Array 类型和完整长度，再逐项验证原始行号并写入新的位置 Map，
  最后检查唯一项个数。未知行、重复行、缺失项和稀疏数组均拒绝；只有完整验证
  成功后才替换公开排列、位置表和导航树。未改变排列仍复用既有快路径。
- 初始导航直接遍历全部原始值进行正安全整数检查，包括 Array 空洞；不依赖
  会跳过空洞的 `Array.some` 或 Map 构造器碰巧报错。大于 32 位的合法行号不截断。
- `prepareOrder` 按输出位置顺序追加 task-group-head/task-gap 边界。无耗时排序时，
  窗口按同一个 plan 的位置单向消费；同位置的多个边界保留原顺序，不能只处理
  一个。同一任务的隐藏行会推迟边界到下一个可见行，新任务头丢弃前一隐藏任务
  尚未展示的边界；末尾无可见行时不留下孤立任务头。
- 耗时排序不投影任务边界；time 顺序本就没有 task 边界。筛选、折叠、切换顺序、
  当前任务提示和导航继续使用完整记录，不从当前 DOM 猜测整个报告。
- 原始记录、ordinal、源码 ID、符号、参数、返回值、地址和任务关系不修改。
  绘制块仍完整校验，不通过少校验几行或改变块大小制造速度改善。

## 成本与限制

新位置表依然是 O(N) Map，导航树、完整排列、可见性/折叠掩码、ordinal 和
完整模型继续驻留。这里移除了 O(N) 的临时 pair 数组，以及一个冗余任务边界
索引和逐可见行的空数组；没有增加新的持久缓存。JS 引擎的对象大小和回收时机
不固定，不据此声称减少了多少峰值 RSS，也不承诺总内存上限。

重建依然同步扫描完整记录；冷 task 分组、冷耗时排序后续投影与分散 HTML 的
DOM 创建仍可能造成长任务。此优化不改变窗口加载策略、4 块 / 16 MiB HTML
资源缓存、160 行挂载上限或完整 Text 回退。此前尝试的 catalog/属性缓存和
`template.content` 解析没有稳定收益，未合入。

## 对照方法

以 `7e210e0a29be` 为基线，使用两份实际 trace、相同不可变报告资源和独立的
index 文件；对照仅替换两个 Text runtime。通过 fgview HTTP 加载，显式
`?text=windowed`，1440×900，三轮交替独立 Chromium 进程；无并行测试、构建
或 CPU profiler。记录 17 项操作的 API 同步前缀、就绪、双 rAF 反馈代理、
Long Tasks 和 API 内 rAF 回调数。后两者不等于实际呈现帧数或任意设备的帧预算。

完整模型、每步完整可见行及导航排列/计数做 SHA-256 对比；每步核对资源请求、
字节和挂载行数，不只检查当前窗口是否看起来正确。输入与模型哈希、原始每轮
结果和测量时实际 runtime 字节保留在本地证据目录。

首次探索后补充了导航构造器的空洞数组检查，最终代码重新测量；探索结果单独
保留，不与正式三轮混算。之前的 CPU profile 仅用于选择热点，不作为延迟结论。

## 回归与复现

模型测试覆盖稀疏/空数组、无效类型、重复或未知行号、大行号、失败原子性、
可见性及快路径缓存；同时核对位置表不再接收完整 entry-pair iterable。
Chromium 用独立的旧边界投影参考核对 54 种组合，包括同位置多边界、隐藏任务、
延迟 gap、末尾隐藏任务、空结果、time/task 与升降序；另保留原有折叠/筛选/
完整排列、取消重试、当前任务提示和大窗口交互回归。

新增 5 项回归，最终专项 **112 项 / 45.538 s** 全部通过。sample、真实内核
golden、默认截图、全量测试和独立安装包验证另有日志及退出状态，不能以专项
通过代替这些更大范围的核验。

- 全量 **1349 项 / 860.219 s**，1346 通过、3 项可选跳过，启用 uftrace、raw
  和 sample 浏览器的 required 检查。既有测试中的未关闭文件/socket
  `ResourceWarning` 在基线日志中也存在，本轮不修改无关测试清理代码。
- 纯 Python wheel、sdist、本机 x86_64 uftrace wheel 均经 Twine 校验和独立
  安装后 14-case smoke；纯 Python/source 各跳过一个内置工具专用 case，
  native 的 14 项全部通过。18 个前端资源逐字节核对，sdist 包含本页和所有
  更新的文档/测试；内置 uftrace 执行权限、5 个 runtime 和 manifest 哈希核验。
- 两份 sample 和 7 份真实内核 golden 的规范化全文除两个 Text runtime 外
