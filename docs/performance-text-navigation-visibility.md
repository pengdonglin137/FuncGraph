# Text 导航批量更新 / Complete visibility masks（2026-11-13）

优化**显式启用的实验性 Windowed Text** 的完整导航更新，而不是只统计当前窗口。
报告重新生成后，在 Text 工具中选择 **Windowed Text**，或对 HTTP 报告使用
`?text=windowed`。默认完整 renderer、自动分流阈值、版本、Timeline 配色和记录
内容不变。[窗口化用法与限制](performance-text-window.md)。

## 问题与实现

这是[既有增量导航](performance-text-navigation.md)的批量入口优化，保留局部更新
和同一份完整索引，不新建另一套导航语义。

[折叠范围复用](performance-text-fold-visibility.md)后，CPU profile 显示每次重建
仍通过 `setVisible` 对所有原始行反复查询 Set，即使可见性根本没有变化。Profile
只用于定位，不作为正式加速比证据。

- 重建按完整、已验证的导航显示顺序生成 `Uint8Array(N)`，一次 `setVisibility`
  提交；该顺序不是折叠掩码的原始 ordinal，也不是稀疏的真实行号。
- 先校验类型、完整长度和所有 0/1 值，再发布任何状态。非法调用不部分更新；
  初次保留私有副本，调用方修改输入不影响导航。支持有 offset 的 subarray。
- 已有缓存时仅对变化项更新隐藏 Set、完整计数、快照和 Fenwick 树；相同掩码
  不再按全模型查 Set/Map。逐行本地修改同步缓存，不会让下一次批量提交忽略变化。
- 实际有效重排清除缓存并重新对齐；无效重排保留原状态，完整排列验证不弱化。
  延迟树重建、源码可展开行导航和快照 identity 保持原语义。
- 绘制时最多 160 个挂载单元仍执行本地折叠投影；不移除合法的 `setVisible`。
  完整 DOM 路径继续使用原逐行 API，未主动启用批量缓存。

完整记录、可见行顺序、源码/参数/返回值、调用关系和折叠语义不变。网络分组/LRU、
512 行解析单位、完整绘制块校验、取消、错误重试和 Full Text fallback 不变。

## 成本与限制

首次批量导航更新增加 **`N` 字节私有缓存**，每次窗口重建另有 **`N` 字节临时输入**。
本轮两种输入每份各约 **70.5 / 363.3 KiB**。实际重排丢弃旧缓存，随后重建；不要求
即时 GC。既有模型、隐藏 Set、树、task/duration ordinal 数组和折叠 hidden mask
另计。默认新建完整 renderer 不主动分配缓存，但 Full Text 回退可能复用已有
导航，因此不能声称回退后立即释放。

仍完整扫描掩码并验证重排，无法消除同步全量模型工作。冷排序、分散 HTML 读取/
解析和布局仍可较慢；没有新自动阈值、Worker 或跨帧重建，也不承诺所有动作更快。
