# 本地报告查看器

`fgview` 是可选的本机只读 HTTP 查看器，用于打开已有报告。普通 FuncGraph HTML 仍可双击离线打开；查看器不新增第三方依赖，不生成 sidecar、不虚拟化 Text、不选择大小阈值，也不减少报告的 DOM 或浏览器内存。

## 使用

安装 FuncGraph 后：

```bash
fgview trace.html
fgview trace.html --open
fgview /path/to/dedicated-report-directory --port 9000
```

源码目录中可运行 `./fgview trace.html` 或 `python3 -m fglib.viewer trace.html`。

- 首行输出就是应打开的完整 URL，包含本次服务专用的随机路径。
- 只绑定 `127.0.0.1`。默认自动选择空闲端口，`--port 0` 含义相同；没有全网绑定参数。
- 只有 `--open` 才启动浏览器。启动浏览器失败时服务仍保持运行，可以手动打开打印的 URL。
- 按 Ctrl+C 关闭服务；旧 URL 随即失效，下次启动使用不同随机路径。
- `--help` 查看选项，`--version` 显示已安装的 FuncGraph 版本。

浏览器设置按 HTTP 源保存。若希望跨次运行复用视图、折叠和过滤设置，应使用相同的显式 `--port` 和主机名；自动端口可能改变源。HTTP 与 `file://` 的设置也各自独立，随机路径本身不会改变源。

## 单文件与目录模式

**单文件模式**只提供指定的 HTML 文件，不能通过猜测文件名访问任何兄弟文件。适用于当前的自包含报告，不会顺带暴露旁边的源码或工作目录。

**目录模式**要求存在 `index.html`，会提供所选目录下普通、非隐藏的文件，包括嵌套 JSON 资源，但不提供目录列表。必须选择独立报告目录：它不是仅允许 manifest 资源的白名单，不能指向包含其他私人文件的整个源码/工作目录。Sidecar 使用此模式读取相对资源。

## 生成 Sidecar 报告

```bash
funcgraph trace.txt --timeline --report-mode sidecar --enable-fold --filter --output trace-report
fgview trace-report --open
```

文本和二进制 raw 输入共用此输出模式；raw 仍需要原生依赖。默认 `--report-mode single`，不会自动切换。Sidecar 必须配合 `--timeline`，输出为独立目录而非文件，并通过 HTTP 打开。

### 超过显式字节阈值时自动切换

```bash
# 示例阈值为 64 MiB，不是内置默认值，也不表示所有环境都适用。
funcgraph trace.txt --timeline --report-mode auto --sidecar-threshold 67108864 --output trace-report
fgview trace-report --open
# 包装脚本默认输出 trace.report，超过 15 万行也保留 Text。
fgreport --report-mode auto --sidecar-threshold 67108864 --open trace.txt
```

Auto 同样需要 `--timeline`，且两种结果的输出目标都为独立**目录**。按假想完整单文件 HTML 的未压缩 UTF-8 字节数判断，包含 Text、内嵌源码、视图数据和脚本；只有严格 `>` 才采用 sidecar，恰好相等或更小均为可离线打开的自包含 `index.html`。阈值是非负整数字节数；`0` 让任意非空报告进入 sidecar。**没有默认阈值**，auto 未指定阈值时在处理前报错。trace 行数、压缩文件体积、外壳大小不作为判断依据，避免相同行数但源码池大小不同的报告被误判。

CLI 输出实际模式、完整 HTML 字节数、阈值和入口路径；进入 sidecar 时还会输出经过 shell 引号处理的 `fgview` 命令。两种结果均可用 `fgview` 打开。目录模式下 `fgreport --open` 在前台启动本机只读服务，按 Ctrl+C 结束，不再打开 `file://` 目录地址。两个选项均支持 INI 默认值/preset，也可用 `fgreport init NAME --report-mode auto --sidecar-threshold BYTES` 保存；显式 `--report-mode single` 覆盖配置的 auto，恢复普通 HTML 文件输出。包装脚本的 single 模式保留原有 15 万行省略 Text 规则（`--text` 可覆盖）；sidecar/auto 则保留 Text，除非显式省略。

生成仍完整渲染一次，并暂存过滤索引；未超限时丢弃该索引。临时磁盘需要容纳完整 HTML、索引，以及超限后的外置资源，不减少解析或符号解析工作。更新已托管目录可在两种模式间切换，入口路径不变；切回 single 也保留旧 sidecar 资源供已打开页面使用，不能仅凭历史资源目录判断当前模式。首次生成的小报告只发布 `index.html` 和隐藏归属标记。下述发布保护同样适用于两种结果。

### Sidecar 加载行为

至少 1 MiB 的外置资源使用单个按需启动的 SHA-256 Worker，原始缓冲区转移而非复制；
通过大小/摘要校验后才解码和缓存。`fgview` 的 CSP 只新增允许本页生成的 `blob:` Worker，
网络仍限同源，不允许远程 Worker。浏览器无 Worker 能力、无法启动或 5 秒内未就绪时，
自动保留主线程完整校验；运行中的 Worker 失败会让当前请求报错，Retry 使用主线程。
取消最后一个正在校验的请求会终止该 Worker；同资源的其他消费者、同 Worker 的其他
校验任务不会被一个消费者误取消。Text 最多预取下一网络块，仍在全部准备后挂载；
这不是视口窗口化。实测、开销和限制见 [Text 交付优化](performance-text-delivery.md)。

- 首次 Timeline 读取完整模型，不获取 Text/Compare/源码正文，不创建逐行 Text DOM。精简的 trace 行号 → source ID 索引仍内嵌；源码 HTML 按最多 64 条源码记录放入 `source-<首个ID>.json`。展开 Text 源码或已打开的 Timeline 调用点面板时只读取对应块；收起的调用点面板等到打开才请求。已解析的悬停位置直接使用 Timeline 紧凑位置，不请求源码 HTML；旧版/未知位置可读取对应块回退。
- 源码块沿用大小/SHA-256 校验和共享请求；等待时显示 **Loading source…**，失败提供 **Retry**，不显示部分代码。收起、替换/关闭详情或离开视图会取消当前消费者，忽略迟到结果；离开时尚未加载完成的展开面板在返回后重新请求，同块的其他消费者可继续完成。新生成报告的 sidecar 源码资源缓存采用 LRU，最多保留 **8 块且合计不超过 16 MiB 的已校验 UTF-8 JSON 字节数**，实际读取或加载命中才刷新顺序。超限淘汰最久未读的块，已显示的源码不消失，需要时重新下载并校验；单块超过 16 MiB 仍可完整查看，但不保留在资源缓存，也不挤掉其他块。chain/flat 按钮继续同步。预算不是 JS heap、并发请求或完整报告的内存上限：单条大源码不会拆开，已填充 DOM 和完整模型仍可能累积。单文件和 auto 未超阈值的输出继续完整内嵌源码，保留离线行为；旧报告需重新生成才能使用此策略。
- Timeline 统一过滤首次读取 `text-index.json`，按 Text 表达式和调用树语义扫描全部 trace 行，不创建 Text DOM。进度可用 Escape / Clear 取消，新查询替代旧查询；失败保留上次结果并提供 **Retry filter**。完整索引缓存至 Text 挂载；下载、解析和调用树准备仍占用主线程及内存。
- 首次进入 Text、跳转 trace 行号或访问 `#L<number>` 时才准备完整 Text。新生成且超过 4,096 条原始记录（含表头）的 sidecar 使用 `text-<first>.html`，每块最多 4,096 条，逐块下载/校验并解析，不先构造一个完整 Text HTML 字符串。小型/旧报告仍使用完整 `text.html`。Text HTML 资源缓存独立限制为最多 4 块、合计 16 MiB 已校验 UTF-8 字节；真实读取刷新 LRU，单块超预算仍可加载但不缓存，预算不约束并发请求、JS heap 或完整报告内存。4,096 条只是 sidecar 内部传输规则，不改变 single/auto 的显式字节阈值。
- Text 在文档外累计全部行与元数据，显示加载/准备进度，期间可返回 Timeline、切换标签或按 Escape；取消会丢弃未挂载节点，不暴露半成品行。分块路径重入复用仍在缓存的资源，已淘汰的块需要重读；旧单资源路径保留原有完整 HTML 缓存行为。全部结果挂载前，**Finishing Text layout…** 先获得绘制机会；最后的初始化/布局仍同步执行，可能阻塞。使用前重新应用当前过滤，成功后释放索引及 Text HTML 资源缓存。完整 Text DOM 随后常驻，不是视口窗口化，也没有 DOM 上限；总打开时间不保证更短。保存的 Text 偏好和行号锚点直接打开 Text。没有索引的旧 sidecar 仍以完整 Text 过滤。
- 资源请求/校验或文档外 Text 解析失败可 Retry；Escape/返回可取消当前视图的等待/准备，迟到结果不会激活旧视图。若最后的 Text 初始化中途失败，提供 **Reload report**，不复用半初始化的监听器/状态。已有报告需要重新生成才能使用新的准备流程。
- 索引和已挂载 Text 的过滤共用完整记录模型。延后加载的 Text 复用已准备的索引模型，或在节点尚未挂载时快照全部原始行，不为准备 Text 额外请求索引。行快照、校验和完整折叠元数据都在准备阶段协作让出执行机会，保留状态反馈和取消入口；最终挂载时才发布完整模型，首次折叠直接复用。挂载前元数据失败可 Retry；取消丢弃部分工作，已校验 HTML 遵循上述资源缓存策略。内嵌 Text 仍保留惰性同步准备。生成的折叠摘要不属于 trace 输入，稳定元数据不受任务/耗时重排影响。释放 `fgData` 输入缓存并不释放这份逻辑模型：记录和完整 DOM 仍常驻。这是将工作纳入可见准备过程，并未移出主线程；完整就绪时间可能增加，初始化/实际布局仍可能阻塞，导航和展示也没有虚拟化。已有报告需重新生成，才能使用这些行为及修复后的 `sort:asc` / `sort:desc` 指令。
- 新分块 Text 仅在浏览器支持 `content-visibility: auto`、内在块尺寸及 `:has()` 时跳过离屏布局；全部原始行仍已挂载，分析不缩减到可见范围。离屏占位按报告现有字体/内边距估算非空行、空行和源码可展开行尺寸，过滤、折叠及重排不读取几何信息即可刷新；已访问块在内容或响应式断点变化后清除浏览器记忆尺寸，避免旧高度留下空白。尺寸估算不是跨字体回退的像素级总高度保证，遇到更长行时横向范围可能增长。选中/聚焦块及展开源码保留正常布局，避免焦点目标和源码高度丢失。远距离跳行立即到达，不跨离屏块做平滑动画；附近导航仍平滑，旧锚点的延迟滚动不得覆盖新键盘目标或其他视图。打印和不支持的浏览器使用完整布局。访问更多块后浏览器样式/布局内存仍可能累积，不代表 DOM/模型内存有界，也不是虚拟列表。
- `--no-text-view` 继续省略 Text，也不生成 Text 资源；`--keep-source` 的源码解析语义不变。
- 挂载后的 Text 也共用非 DOM 的折叠成员、计数与可见性模型。过滤及 Clear 保留祖先折叠，展开仍尊重被拒绝的行，只恢复可见行保存的源码状态。普通折叠按预建的精确成员范围访问子树，不再为查找成员扫描全 trace；批量折叠只投影实际改变状态的子树并集，每行一次，任务交错的其他行不被包进范围。范围索引增加准备和常驻内存成本，深度控制及完整 DOM 布局仍有全量工作；该折叠索引与上述网络分块独立，并不提供窗口化，已有报告需重新生成。
- Text 导航索引完整数字行号及源码展开能力，不保存 DOM 节点。延后准备在挂载前采集这些事实，完成后才发布；取消/重入遵循上述资源缓存策略。少量可见性变化增量更新计数树，最近/循环目标及首末跳转按秩查找，不再因局部折叠刷新全表候选。大量变化改为延后一次线性重建，避免全量过滤逐行更新树；重排仍提交完整展示排列并保留选中行身份。初始准备、全量过滤/重排、源码展开、原生焦点/滚动和完整布局仍有全量或 DOM 工作。这不是窗口化渲染或有界内存；实测与边界见 [Text 导航性能记录](performance-text-navigation.md)。

产物含 `index.html`、隐藏归属标记及不可变的 `data-<report-id>/` 资源（manifest、Timeline、可选 Compare、完整 Text 和源码块），记录精确 UTF-8 字节数及 SHA-256。共享/归档必须携带**整个目录**，不能只复制 index.html。

本地 72,176 行 trace 实测，完整 Timeline 就绪中位数由 1.87s 降到 0.34s，采样 renderer RSS 由约 758 降到 202 MiB；但首次完整 Text 挂载单次仍需 8.46s。不是所有机器/trace 的性能承诺，方法、限制与可复测脚本见[设计 §8.7](design.md#87-显式-sidecar-的首次-timeline2026-11-10)。

发布先在目标同级目录完整生成、同步。新/空目录仅在全部成功后发布；拒绝非空且无标记的目录、文件目标及输出符号链接。更新已标记资源包时先发布新版本资源，最后原子替换 index.html；失败保留旧入口。旧资源目录故意保留，保证已打开页面仍能读取，所以反复更新会增加磁盘占用；清理时先关闭旧查看器/页面，再删除旧资源包目录后重新生成，或改用新的独立目录。

查看器通过打开的目录句柄固定所选根目录；不提供根下的符号链接、路径逃逸、隐藏路径、FIFO 或其他非普通文件。若显式选择的入口路径本身是符号链接，则选中其解析后的目标。平台必须支持目录相对且不跟随符号链接的文件访问；缺少能力时明确报错，不降级成不受限服务器。

## Text 横向阅读

新报告把 Text 正文的横向滚动与页头、标签页和工具栏分开；超长参数、符号、路径和源码仍完整保留，不截断 trace 来适应屏幕。触屏横滑、鼠标/触控板横向滚动，以及 `h` / `l`（含大写）只移动正文，输入框不拦截这些字母。纵向滚动仍属于整页，不增加一个嵌套的纵向列表。行号锚点、键盘纵向导航和视图往返保留横向阅读位置；过滤移除内容或窗口变宽时，浏览器仍可按实际范围收敛位置。

分块 sidecar 继续跳过离屏布局，并记住已布局块的横向尺寸，避免远跳后因宽行暂时离屏而把阅读位置复位。尚未访问的更长行仍可能增加横向范围。内容/响应式尺寸失效策略保持不变；这不减少 DOM、模型或加载记录数，也不是有界内存或虚拟列表。单文件和 sidecar 均适用，旧报告需重新生成。实现、实测与边界见 [Text 横向阅读记录](performance-text-viewport.md)。

新报告的行号复制、源码单击/双击共用正文级事件委托，不再为每条 trace 行绑定这些处理器。原有键盘、触屏、源码链接、折叠和文本选择方式不变；重排和视图切换不重复绑定。旧报告需重新生成。这减少事件处理开销，但完整 DOM/模型仍保留；[实测与边界](performance-text-interactions.md)不等于窗口化完成。

## 安全与加载边界

只支持 GET/HEAD。请求必须使用有效的回环 Host 和本次随机路径；显式跨源 Origin 被拒绝，没有 CORS、上传、编辑、删除或 shell 接口。响应禁止缓存和 MIME 嗅探、限制跨源读取，并提供兼容报告现有内联脚本/样式及同源 fetch 的内容安全策略。

请只打开可信报告。报告的 JavaScript 仍会在浏览器中执行；查看器不是 HTML 净化器或安全沙箱。随机 URL 不是多用户认证，获知地址的本地用户仍可读取所选资源。不要将它当作公开报告共享服务。

启动不会解析或提前读取 Timeline、Text、源码资源；发送文件时每次读取不超过 1 MiB，HEAD 不读取正文。这只限制查看器的传输缓冲，不限制浏览器内存。完整性校验、取消和重试仍由 `fgData` 负责，普通报告依然内嵌全部数据。

## 常见问题

- **Sidecar data needs HTTP**：对包含 `index.html` 的独立报告目录运行 `fgview REPORT_DIRECTORY`，打开打印的 HTTP URL，而不是 `file://`。
- **404**：确认资源存在、是非隐藏普通文件且路径不经过符号链接。单文件模式本来就拒绝兄弟资源；完整外部资源包应使用目录模式。
- **403**：使用打印的地址，不要改成自定义域名或从其他源发起请求；这些请求被有意拒绝。
- **端口被占用**：省略 `--port` 或使用 `--port 0` 自动选择端口。
- **缺少 index.html**：目录模式不浏览文件夹；应指定单个 HTML 文件或正确的独立报告目录。
- **平台缺少安全文件访问能力**：使用支持目录相对 no-follow 访问的平台，不提供不安全回退。单文件 HTML 仍可脱离查看器离线打开。
