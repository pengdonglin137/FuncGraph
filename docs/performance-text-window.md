# 实验性 Text DOM 窗口（2026-11-13）

这是可以实际滚动、跳行和筛选的窗口 renderer，不再只是离文档取块接口。
新生成的分块 sidecar 中，Text 达到 **65,536 条记录**（含表头）或未压缩正文
达到 **64 MiB** 时，默认开启窗口化。普通 `single`、小型 sidecar 和旧报告的默认行为不变。
这个阈值只选 Text renderer，不负责将单文件切换为 sidecar。

后续消除完整行定位、相同导航和耗时排序的重复工作，并修复视口反馈抢占重建的
竞态；两种规模的三轮结果与未解决瓶颈见[Text 重建性能](performance-text-rebuild.md)。
排序后的分散窗口还会[合并同一网络资源的读取](performance-text-block-locality.md)，
减少缓存淘汰造成的重复传输；不会跳过所需绘制块的完整校验或缓存离屏 DOM。

## 使用 / Quick start

```bash
funcgraph TRACE --no-config --timeline --enable-fold --filter \
  --report-mode sidecar --output report-directory
fgview report-directory
```

大报告直接打开 `fgview` 输出的 HTTP URL 即可。对分块报告，可在原地址加
`?text=windowed` 或 `?text=full` 显式指定模式；已有查询参数时用 `&`，锚点始终
放在最后，例如 `index.html?text=full#L50000`。不要丢掉 `fgview` 的随机路径前缀。
Text 主工具栏的 **Full Text** 按钮就地加载完整正文；完整正文状态下，同一个按钮会变为
**Windowed Text**。窄触屏也可直接切换，无需展开 **More**。分块报告在 360px 及以下的触屏上
用圆点表示筛选已启用，**In Timeline** 不在按钮正文重复目标行号；完整状态和行号仍保留在
无障碍名称中。两种模式之间切换不重载页面，
并保留当前筛选、排序和阅读位置；目标分块
验证通过前，完整正文仍可用。准备期间按钮会移动到固定的底部状态条，点取消、按 Escape
或切换视图都可中止；出错可在原位重试。
窗口初始化失败时，可 Retry 或选 **Open Full Text**，不会静默切换为大 DOM。

New chunked sidecars default to windowed Text at **65,536 records** or **64 MiB**
of rendered Text HTML. `?text=windowed` and `?text=full` override that choice.
Ordinary single-file reports, unchunked sidecars and older exports keep their existing defaults.
The renderer still requires a complete presentation index (v4 or later).
The same Text toolbar button toggles between **Full Text** and **Windowed Text**
without reloading, even on narrow touch screens with **More** closed. It keeps
filters, ordering and the reading position. During
preparation, cancellation moves to a fixed bottom status bar; Escape and view
changes also cancel. If row validation fails, the full document stays open and
you can retry.

`ping3` 实测（本地 Chromium，离线 gzip）：从 Full Text 切回后，挂载行数从
82,529 降到 160，保留深滚动锚点、Timeline 选中调用及 URL/历史。

此前从 Windowed Text 展开完整正文时，筛选的增量更新漏掉了显隐未变的新分块，
使离屏分块的占位高度为零。深跳会把大量分块挤进同一帧，触发整页布局和绘制。
现在切到 Full Text 时初始化全部分块的占位高度；切回时先移除旧正文，再换布局样式，
避免给即将淘汰的大 DOM 重算样式。三轮交替同机对照，中位数如下（不含首次展开
完整正文的准备时间，从 `L63551` 深跳开始计时，直到切回后再过两帧）：

| 路径 | 深跳到窗口就绪 | 最长主线程任务 |
| --- | ---: | ---: |
| Windowed → Full Text 后深跳，再切回 | 9.87 s → 244 ms | 8.70 s → 107 ms |
| 直接打开 Full Text 后深跳，再切回 | 2.11 s → 252 ms | 1.96 s → 104 ms |

原始采样与 Chromium 性能追踪见 `build/benchmarks/20261119-text-handoff-cdp/`。

窗口切到 Full Text 时，无筛选、隐藏事件或折叠的时间顺序正文，可复用分块校验时统计的
行数及现有导航显隐，不再在挂载后扫描每一行。任务排序、筛选、折叠和带行内样式的
文本块继续用逐行投影。仍然完整校验并挂载正文；这不是 Full Text 的 DOM 或内存上限。

`ping3` 的 82,529 行离线 gzip 报告（Chromium 145、1500 × 900，四轮交替对照）：
挂载后的投影阶段中位数从 **173.8 ms 降到 2.6 ms**，最长主线程任务中位数从
**329.5 ms 降到 157.0 ms**，包含准备和两次动画帧的总耗时从 3.11 s 降到 3.02 s。
每块占位行数与原实现一致；切回窗口模式仍保留深滚动位置，最多挂载 160 行且不增加历史条目。
原始采样见 `build/benchmarks/20261119-trace-jump/full-text-counts-real.json`。

- 最多挂载 **160 个展示单元**，其中包含 trace 行或任务分组标题；trace 行数不会超限。
  每条所需行的源码占位一并挂载，离屏行不保留 DOM 缓存。
- 完整记录参与过滤、调用树/深度折叠、折叠摘要、time/task/duration 排列和键盘导航。
  原始行号可以稀疏；网络资源仍按原始 ordinal 定位，不按当前排列位置猜测。
- 滚动高度通过数值索引估算，再由已挂载元素的实测高度修正；展开源码、窄/宽屏切换
  会更新尺寸。估算不是整篇文档的精确排版；首次到访不同高度区域仍可能修正滚动条。
- 点击源码、hash、Timeline → Text 和键盘跳行可以进入未挂载区域。取消或后到的旧请求
  不得覆盖新目标；离开 Text 取消窗口/完整回退的读取，重新进入可继续浏览。
- 源码展开状态随稳定行保留；行淘汰时取消它的源码订阅，回来时按需恢复。
  若新进入窗口的展开行需要同一源码分块，会接续正在下载的分块，不取消后重下；
  没有订阅的分块仍立即取消。
  过滤临时关闭源码面板，不抹掉原有展开状态。
- 块失败显示重试；导航失败保留原窗口，筛选失败回滚到上一个完整筛选结果。

### 只更新实际变化的行高

窗口行的 ResizeObserver 直接使用边框盒高度，只更新变高或变矮的行，并保留阅读锚点。
切回 Text 时，即使隐藏期间行的内边距变了，当前阅读行也不会因此跳动。首次挂载、显式批量操作和
不提供边框盒尺寸的通知仍可同步测量。宽度和水平滚动范围仍单独检查。

离线 `ping3` 在 Chromium 145、1500×900、4× CPU 限速下做了五轮交替对照：定位到第 63551 行后，
对上方已挂载行的源码展开、收起各四次。几何读取从首次 320 次、此后每次 160 次降为 0；
源码文本、阅读行位置和滚动范围一致。没有变化的标签往返本来就是 0。本测试统计 JS 逐行几何读取，
不是浏览器布局次数或端到端延迟。记录见 `build/benchmarks/text-row-resize/paired.jsonl`。

### 同一滚动帧复用正文位置

窗口调度、可见区间和吸顶任务标题共用一次正文位置读取。按时间排列时，不读取任务标题所需的工具栏位置，
也不重复修改已隐藏的标题。`ping3` 的 8 次窗口内滚动中，窗口调度的正文位置读取从 **24 次降至 8 次**，
按时间排列时的工具栏位置读取从 **8 次降至 0 次**。计数不包括独立的引导线绘制；阅读位置、任务标题和
挂载行保持一致。记录见 `build/benchmarks/20261122-text-scroll-geometry/ping3-audit.jsonl`。

### 相邻窗口保留重叠行

滚动到相邻窗口时，顺序未变的重叠行不离开 DOM，焦点、源码和行高监听会随行保留。
只移除离开窗口的行，并同步测量新进入窗口的行。重叠行真正变高或变矮时，仍由
ResizeObserver 更新。筛选、重新排列和不重叠的跳转仍走完整窗口替换，挂载上限仍为 160。

在同一份离线 `ping3` 上，用 Chromium 145 从 `L63551` 开始做了两轮交替对照。
下表的两个计数分别记录窗口正文移除的 DOM 节点数，以及 JS 同步读取的行高数，两者在此测试中相同。

| 操作 | 移除节点 | 行高读取 |
| --- | ---: | ---: |
| 1500×900，向下滚动 | 160 → 98 | 160 → 98 |
| 1500×900，向上滚动 | 160 → 30 | 160 → 30 |
| 667×375，触屏模拟上滑（向下滚动） | 160 → 104 | 160 → 104 |

每组的新旧窗口行序和最终滚动位置一致，旧版丢失的重叠行焦点在新版保留。此处不是
真机测试或延迟测量。记录和复测脚本见 `build/benchmarks/text-window-slide/measured.jsonl`
及同目录的 `measure.py`。

重叠行也不再重复初始化折叠按钮和源码状态；筛选、折叠、重排等显式操作仍更新整个窗口。
沿用同一份 `ping3`，保留 `L63645` 的折叠摘要和 `L63654` 的已展开源码，桌面向下
滚动的两轮交替对照中，初始化的 trace 行从 160 减少到 97。摘要节点不再替换，内容、
焦点、行序和最终滚动坐标与上一个版本一致；随后展开仍能显示被折叠的子调用。
记录见 `build/benchmarks/text-window-projection/paired.jsonl`。

## 整篇文档操作 / Whole-document actions

**Copy** 从完整可见行排列生成原始 trace 文本，涵盖所有未被筛选/折叠隐藏的行，
不是只复制这 160 行；不附带源码正文或 UI 生成的折叠摘要。

**Full Text** 在成功准备全部行之后替换窗口，保留筛选、折叠、排列和源码状态。
准备时进度和 **Cancel Full Text** 在固定底部状态条显示，可点取消或按 **Esc**；取消不替换窗口，
也不会执行待完成的全选、查找提示或打印。失败同样保留窗口，可重试。
完整正文开始挂载后不再可取消，也不再有窗口 DOM 上限。
**Collapse All** 不再切换为完整 Text：它收起当前筛选和折叠范围内的全部源码（包括
滚动区外的可见记录），保留隐藏记录的展开偏好，取消已挂载源码的待完成请求，并修正
离屏高度，尽量维持阅读位置。只处理已保存的展开状态和当前窗口，不为收起额外下载正文。
**Expand All** 保持窗口化，把当前筛选和折叠范围内的全部源码标记为展开。
只为已挂载的行读取源码；滚动或跳到离屏行时按需读取。不改变隐藏行的展开状态。
**Ctrl/⌘A、Ctrl/⌘F、Ctrl/⌘P** 仍先使用完整回退，
不把当前窗口当成整篇文档。全选在准备完成后执行，打印随后打开浏览器打印界面；
原生查找需要在提示 Full Text ready 后**再按一次快捷键**。
直接使用浏览器菜单打印窗口模式时输出明确提示，避免静默打印不完整的 trace。

普通鼠标/触摸文本选择固定当前窗口，直到清除选择；跨窗口连续原生选择尚未提供。
如需整篇选择、浏览器查找/打印，或希望不受窗口淘汰影响，请先点 **Full Text**。
Full Text remains the correctness fallback for whole-document browser operations.
The experimental renderer does not claim native selection or find across unmounted DOM.

## 数据与边界

- 耗时排列缓存未命中且超过 16,384 行时，有限值用 1024 项有序段和稳定归并，
  按约 8 ms 批次协作式调度；期间保留旧窗口。小输入及 NaN/Infinity 等仍原生
  排序，后者保留旧对象比较器。取消的结果和进度不发布；同宽恢复、导航等待和
  Full Text 失败重试均处理未完成排列。临时 typed buffers 共 `16 × N` 字节，
  输出和模型另计，不跳过完整导航校验。[排序测量与限制](performance-text-cooperative-ranking.md)。

- 导航可见性按完整显示排列一次提交二进制掩码，先验证再更新，仅应用实际变化项。
  私有缓存和每次临时输入各为 `N` 字节，和下述折叠掩码、ordinal 数组分别计费；
  普通逐行更新同步缓存，实际重排清除缓存并重新对齐。新建的默认完整 renderer
  不主动分配该缓存，但 Full Text 回退可能复用既有导航，不能保证立即释放。
  不改变完整重排校验或最多 160 个挂载单元的投影；[测量和限制](performance-text-navigation-visibility.md)。

- 窗口重建复用原始记录 ordinal；无筛选时折叠状态使用现有范围生成按次字节掩码，
  有筛选时保留逐匹配记录的 predicate。掩码每行 1 字节，无匹配范围不分配；
  实现、实测及剩余阻塞见[折叠范围优化](performance-text-fold-visibility.md)。任务 plan 和当前
  耗时排列各增加 `4 × N` 字节的 typed array，时间原序无需该数组。共享任务 plan
  的默认完整 renderer 也承担前一项内存成本。完整模型仍遍历，不能据此保证逐帧
  响应；稀疏/密集折叠对照及内存边界见[重建热点优化](performance-text-geometry.md)。

- sidecar presentation index **v4**：原有 14 个过滤字段之后依次追加 `space`、
  `sort-duration`、`fold-ret`、`call-depth`，最后仍为实际 source ID/null。
  源码 0、零返回值、原始返回表示、精确排序耗时及空值语义均保留；旧 v1/v2/v3 可读。
  本次真实 trace 的索引从 34,646,118 增至 36,233,756 字节（增加 1,587,638 字节），
  这是保留展示语义的交付成本；18 个 Text HTML 资源逐字节不变。
- 当前 **v5** 在 v4 的 `call-depth` 与 source ID 之间追加 `raw-func`，仅在原始符号与
  展示名不同时记录原始名称；完整 DOM、sidecar 筛选和实验窗口均保留它。精确函数筛选
  不会合并 `.isra.0` 等不同符号，旧正则仍使用展示名，v1–v4 读取保持兼容。
  上述索引字节数是 v4 阶段测量值，不是 v5 的体积测量。
- HTML 资源仍以最多 **4,096 条记录**为单位；sidecar 每次解析目标 **512 条** paint block，
  离线 `single-windowed` 使用 **128 条**。Full Text 按资源批读后逐块校验，最后整体挂载；
  不宣称 HTTP Range 按 160 行交付。四个任务以内并发读取所需 paint block，排序后一个
  窗口可能涉及多个资源。暂时的解析 DOM 与已挂载 DOM 是不同预算。
- 按需解析会核对每行 ID、内容、完整属性及 source 配对。完整 renderer 仍保留原先
  DOM/模型行数覆盖校验；实验 renderer 另校验完整模型/catalog/navigation 一致。
- 完整元数据、折叠/导航/高度索引和 Timeline **仍为全量**；源码正文大小也不由行数
  限制。已有 HTML 与 source LRU 继续独立计数，不能当作整进程或峰值内存上限。
- 当前只在 Chromium 实测；没有据此宣称其他浏览器或任意百万行 trace 已完成验收。
  大模型解析、重排、GC 仍可能产生长任务；以后还需协作拆分、模型压缩与更多 trace 验收。
- task 分组时，原始标题仍随首个可见记录进入窗口；滚动越过标题后，以一条固定提示
  延续当前视口的任务上下文，原始标题被淘汰后仍有效。提示由完整可见分组边界定位，
  不依赖选中行或仅当前 DOM；沿用现有标题配色，不新增 trace 行或扩大 160 行预算。
  它位于横向滚动容器之外，窄屏单行省略、完整内容保留于 title；行数始终描述完整组。
  时间/耗时排序、无结果或离开 Text 时隐藏，Full Text 清理，Copy/打印不包含提示。

## 真实 trace 三轮对照

输入 `/tmp/pi4/traceB.txt`：10,453,189 字节，72,176 原始 Text 行、55,186 调用、
55,213 帧、12 条轨道。输入 SHA-256：

```text
5954b07778c00623e0bb7324cd5e78130bb5188463ab7a3ca061eb89b2f1ab62
```

同一个新生成 sidecar，通过真实 `fgview` HTTP 服务，Chromium **145.0.7632.6**、
1500×900；先打开 Timeline，再测冷 Text。六个独立浏览器，三轮 complete/windowed
交替顺序；计时及内存取样期间不并行运行测试/打包。不是与旧版本或不同数据集混比。

| 三轮中位数 | 完整 Text | 窗口 Text |
| --- | ---: | ---: |
| Text API 就绪 | 2,359.4 ms | 798.4 ms |
| 再等待两次 rAF 的反馈代理 | 2,392.4 ms | 811.9 ms |
| 就绪窗口内最长主线程任务 | 165 ms | 92 ms |
| 已挂载 trace 行 | 72,176 | 160 |
| 整页元素 | 792,534 | 2,369 |
| 完整模型记录 | 72,176 | 72,176 |
| 首次 Text 资源数 | 18 HTML 块 | 1 索引 + 1 HTML 块 |
| renderer VmRSS 合计取样 | 751.4 MiB | 365.4 MiB |
| JSHeapUsedSize 取样 | 33.4 MiB | 75.4 MiB |

就绪中位数约减少 **66%**；RSS 只是已知进程取样，不是峰值或严格上限。窗口模式的
JS heap 取样**反而更高**，因为完整 JSON 文本/元数据及数值索引仍常驻，不能将 DOM
减少等同于所有内存类别都减少，也不能从这组取样推断内存泄漏或确定的回收时机。
三次就绪原始值分别为 complete 2,359.4/2,526.6/2,335.1 ms，windowed
798.7/784.7/798.4 ms；保留所有轮次，没有用最佳值代替中位数。

计时后另外跳往原始中/末/首行；窗口模式中/末冷跳行中位数为 90.8/73.3 ms，
完整模式为 50.6/51.2 ms。按需下载需要付出代价，**不是所有操作都更快**。
六次完整模型的标准化摘要均为：

```text
bfcd594748ec635ac430b942433cff198a922f635af4ddf97573afe30fc1f9c6
```

摘要逐项包含全部原始行号、文本、14 个过滤属性及 source ID，不只比较数量或首屏。
v4 的新增展示属性另外在导出/按需读取测试中核对。

复现：

```bash
funcgraph /tmp/pi4/traceB.txt --no-config --timeline --enable-fold --filter \
  --func-links --report-mode sidecar --output /tmp/text-window-report
PYTHONPATH=.:tests python3 tests/benchmark_textwindow.py /tmp/text-window-report \
  --trace /tmp/pi4/traceB.txt --rounds 3 --output /tmp/text-window.json
PYTHONPATH=tests python3 -m unittest -v test_textwindow test_textindex test_textmodel test_textchunks
```

### 离线排序后的跨块跳窗

在 `ping3` 上，耗时排序后的窗口经常跨许多原始数据块。把离线解析块从 512 行改为
128 行，减少必须解析并校验但不会挂载的行；4,096 行资源边界和 160 个挂载单元上限不变。
Full Text 按资源批读，在每批内分时段解析，最后仍校验并挂载完整数据，可在交接前取消。

Chromium 145 独立进程交替三轮，本机就绪中位数：跳到耗时排序下一窗 **500 → 292 ms**，
跳回首窗 **393 → 259 ms**，`func:mutex` 筛选 **430 → 254 ms**。首次进入 Text
**260 → 256 ms**，Full Text **7.43 → 7.50 s**；仅缩小解析块而没有批读时约需 9.81 s。
每轮完整模型和各操作可见行/导航顺序摘要一致；Full Text 均挂载 82,529 行。原始日志在
`build/benchmarks/20261119-ping3-window-filter/`。

进一步对比 128、64 和 32 行块：在 Timeline 应用 `sort:desc` 后首次跳到 `L82255`，
目标窗口分散在 20 个离线资源中。Chromium 4× CPU 降速下，每版交错测五次，跳至目标行
的中位数分别为 **3.16 / 2.47 / 2.05 秒**；三版完整排序相同，仍仅挂载 160 行，返回保留
原切片和时间范围。常速普通首开每版三次，中位数都约为 0.24 秒；Full Text 中位数为
**3.31 / 3.35 / 3.54 秒**，均挂载完整的 82,529 行。

因此离线报告采用 64 行块，兼顾分散窗口和 Full Text。4,096 行资源边界、校验、挂载上限
及 sidecar 格式均不变；已有报告可继续打开，但要重新生成才能改变块大小。结果仅适用于
该样本，不是屏幕呈现时间。记录见 `build/benchmarks/20261121-sort-only-handoff/`。

纯耗时排序和没有条件的筛选直接使用索引的总行数，不再遍历正文。窗口读取超过约
300 ms 时，在已有状态栏显示 `Loading Text rows: 已读 / 待读…`；只计入已经完成校验的
目标窗口新行，不表示全量 trace 的进度。等待期间不会提前替换行；完成、失败或返回取消时
清除进度，失败仍可重试。390×420 触屏模拟中，进度和返回按钮均在视口内。

上述 `ping3`、`sort:desc`、4× CPU 降速场景再次每版交错五次，筛选阶段的中位数
**16.3 → 0.4 ms**，跳到目标行仍约 **2.5 秒**，未测得端到端提速。完整排序、挂载行数和
返回的切片及时间范围一致。记录见 `build/benchmarks/20261121-window-block-scheduling/`。

### 减少 Full Text 块校验的临时分配

校验每个 Text 块时复用该块的属性名，按已验证的索引列顺序逐项比较，避免为每条记录创建回调、反复拼接属性名并查询列名。行标识、源码引用、正文与全部展示字段仍须匹配，失败时不发布该块。

在离线 `ping3` 上，Chromium 145 五组交错 A/B 的累积块解析与校验中位数为 **1,983.5 → 1,884.5 ms**，切换到 Full Text 的完整耗时为 **2,995.9 → 2,894.9 ms**。每次均挂载 82,529 行、645 块，正文区域序列化 HTML 的 SHA-256 一致。配置与原始数据见 `build/benchmarks/20261119-trace-jump/full-text-validation-ab.jsonl`。

另一次在 4× CPU 降速下采集的首击 trace 中，保留 Full Text 的 16 次试验有两次包含约 91–92 ms 的主线程垃圾回收；另一长尾包含交叉观察检查和解压工作。此次校验优化只验证了 Full Text 加载耗时，没有证明首击长尾消失。trace 摘要见 `build/benchmarks/20261119-trace-jump/full-text-click-tail.jsonl`。

### Full Text 挂载后的布局

Full Text 仍把完整 trace 挂载到 DOM，但对至少 4,096 行且支持相关 CSS 的报告，复用完整
Text 的分块延迟布局，避免恢复焦点时同步布局所有离屏行。打印时所有块都可见；不支持该
布局能力时仍使用完整 DOM 的原布局。最后一批校验完成后显示正在完成布局，交接前仍可取消。

`ping3` 同机 Chromium 145 三轮交替对照：Full Text API 就绪中位数 **7.50 → 3.13 秒**，
再等两帧 **11.41 → 3.17 秒**，最长主线程任务的中位数 **5.01 秒 → 611 ms**。每轮均
挂载 82,529 行，原始行号、原文和源码配对摘要一致。打印和全选仍需处理完整文档；这不是
内存上限或无长任务的保证。记录在 `build/benchmarks/20261119-ping3-full-text/`。

在此基础上，按时间原序进入 Full Text 时直接挂载已校验的正文块，不再拆散并重组每行；
任务分组和显式耗时排序仍按原逻辑生成。相同报告另做三轮交替对照，就绪后等两帧的
中位耗时 **3.20 → 2.81 秒**，最长主线程任务的中位数 **618 → 272 ms**。完整行数、
原文和源码配对摘要不变；日志在 `build/benchmarks/20261119-ping3-full-order/`。

窗口 Text 首次从 `#L<n>` 或 Timeline 跳入时，会直接准备目标所在的窗口，不再
先加载报告头部。这个快路径适用于能在当前顺序和可见性下定位的行；已有过滤条件
继续走原来的过滤准备路径，切走或改变目标不会让迟到的窗口抢回焦点。

在同一 `ping3` 报告上冷打开 `#L81000`，Chromium 145 的 Text HTML 请求从
两个块（10,925,869 字节）降为目标单块（5,543,950 字节），正文传输减少约 49%。
完整索引仍然加载，未计入上述 HTML 字节。目标行在可见区内获得焦点，仍只挂载
160 行。测量记录在 `build/benchmarks/20261119-ping3-anchor/`。

### 首次定位折叠内的行

没有待应用过滤时，首次从 Timeline 打开 Windowed Text 可直接准备折叠目标附近的窗口；不再先加载开头的行块。临时展开与目标行一起提交；返回 Timeline 或换到另一个锚点会取消旧跳转，不改折叠状态。9,000 次调用的 sidecar 回归中，首次定位折叠内的 `L8500` 从读取 `text-0.html` 和 `text-8192.html` 两个块减少为只读取 `text-8192.html`，仍最多挂载 160 行。

在相同 `ping3` 采集数据的离线预览（320px 触屏）中，第一次跳到折叠的 `L40277` 从读取起始块和目标块变为只读取目标块；前后均只挂载 160 行，返回后仍选中同一调用。

Timeline 已应用的过滤也参与首窗准备：匹配目标时直接在目标位置绘制过滤结果；目标被排除时只绘制过滤后的默认窗口，不读取或展开目标。`ping3` 使用 `duration:>0` 首次跳到折叠的 `L40277`，同样从读取起始块和目标块降为只读目标块，最多挂载 160 行。过滤构建失败时回退到已提交结果，不清除原查询。

折叠索引构建合并了祖先表查找，单层祖先不再额外分割或去重。对 `ping3` 首次跳至 `L4723`，
在 Chromium 145、4 倍 CPU 降速下做 9 组交错对照：折叠索引执行时间中位数为
**188.2 → 174.4 ms**，含调度等待的阶段时间为 **305.1 → 290.6 ms**，点击到目标高亮为
**1110.3 → 1096.3 ms**。主要收益在折叠索引，首跳总耗时只小幅下降；最多仍挂载 160 行，
目标仍获得焦点。测量记录在 `build/benchmarks/text-fold-lookups.Qm99lI/`。

Windowed Text 的分批准备优先使用可取消的浏览器任务队列，避开连续定时器的等待；不支持时仍用定时器。
第一轮前仍等待加载提示绘制，每批仍检查 8 ms 时间预算；离开 Text 会取消未执行的任务。
同一 `ping3` 离线报告，仅切换队列实现，Chromium 145、4 倍 CPU 降速、9 组交错对照：
`L4723` 从点击到高亮的中位数 **1095.3 → 1024.0 ms**，9 组中有 8 组更快。
挂载仍不超过 160 行，目标获得焦点，返回时保留同一切片及视野。这项改动减少的是批次间等待；
最长帧间隔的中位数仍约 411 ms，不代表首跳卡顿已消除。记录及脚本在
`build/benchmarks/text-startup-schedule.poZR6k/`。

离线 gzip 报告的 Text 索引达到 8 MiB（解压后）时，后台 Worker 负责解压、UTF-8 校验和
JSON 解析，按每批 1,024 行传回；行全部到齐后才缓存，取消最后一个订阅者会终止 Worker。
小索引、未压缩索引、sidecar 与不支持 Worker 的浏览器仍走原路径。尺寸错误、截断与解析
错误不写入缓存。真实 `ping3` 的 82,529 行索引在两条路径上的完整 JSON 摘要一致。

Chromium 145，真实 `ping3` 首次跳至 `L4723`，仅切换索引解码实现。在 4 倍 CPU 降速的
7 组交错对照中，从点击到高亮的中位数 **1080.3 → 895.3 ms**，最长动画帧间隔的中位数
**416.7 → 197.9 ms**。在不降速的 5 组对照中，点击到高亮 **268.4 → 317.4 ms**，最长帧间隔
**107.7 → 56.6 ms**；传输增加了就绪耗时，但减少了页面连续无法更新的时间。各轮仍只挂载
160 行，保持焦点和返回视野。帧间隔为浏览器回调代理，不是实屏帧率，也不是响应时间上限。
脚本、索引剖析和数据在 `build/benchmarks/text-index-decode.QQNIdC/`。

导航索引现在在每个 512 行的准备批次内构建行位置、可展开行和导航计数树，不再在最后一次性
遍历整张表。位置表也用于校验重排成员，省去重复的行号集合；失败的重排不改已生效的顺序。
复用同一 `ping3` 离线报告，仅替换索引实现，Chromium 145、4 倍 CPU 降速、7 组交错对照：
`L4723` 点击到高亮的中位数 **816.0 → 762.6 ms**，最长动画帧间隔 **174.2 → 126.9 ms**。
不降速的 5 组对照为 **295.5 → 280.0 ms**、**56.4 → 42.2 ms**。各轮仍只挂载 160 行，
保留行焦点和返回视野；回归另核对了稀疏行号、边界跳转、过滤与重排。记录在
`build/benchmarks/text-paint-first-jump.2FGbFC/`。

未筛选、未隐藏行且按时间顺序的首窗，直接复用完整行序与原始行号索引，用统一估计行高生成
初始滚动位置，不再逐行重建同样的可见排列和位置表。稀疏行号仍按原始索引查找；筛选、折叠、
隐藏事件、任务分组和耗时排序继续使用完整可见性投影。

相同 `ping3`、Chromium 145、4 倍 CPU 降速，仅替换首窗投影：各 7 对中，`L4723` 最长动画帧
间隔中位数 **138.0 → 111.2 ms**，`L40004` **115.6 → 105.7 ms**。点击到高亮分别为
**840.0 → 864.0 ms** 和 **724.9 → 711.4 ms**，未见一致的端到端提速。不降速的 5 对
`L4723` 为 **278.9 → 273.7 ms**，最长帧间隔 **35.1 → 40.1 ms**。这项改动主要改善了
降速时的长帧，两处目标仍只挂载 160 行，保留行焦点和返回视野。记录在
`build/benchmarks/text-window-commit.H7FKwj/`。

### Timeline 跳到 Text 后的高亮

目标行就绪后，在下一帧滚动并高亮，不再固定等 30 ms。切走或改选目标后，过期请求不再
触发滚动和高亮；只有重复高亮同一行时，才为了重启动画同步读取布局。

本机 Chromium 145 对 `ping3` 的同一组调用做前后对照，每种模式跳转 14 次，舍去前两次。
从点击到应用高亮的中位数：窗口 Text **32.1 → 14.5 ms**，Full Text **62.7 → 36.7 ms**。
从点击到高亮后的第二个动画帧回调分别为 **63.6 → 47.2 ms** 和 **81.4 → 65.1 ms**。
这些是浏览器内时间点，不是屏幕呈现时间，也不包含首次打开 Text；Full Text 的布局开销仍在。
在 320、480 和 1500 px 宽度验收了函数名显示和返回 Timeline 原切片、原视野；也验证了从
Text 的调用入口、出口及无对应切片的行跳出后，能返回原滚动位置。记录在
`build/benchmarks/20261119-trace-jump/`。

### 首次打开 Text 复用已提交的筛选结果

在 Timeline 应用筛选后首次打开 Windowed Text，只要提交的筛选状态和索引实例都没有变化，
就沿用同一份全量匹配集和排序方向，不再扫描索引或向 Timeline 重发筛选结果。目标窗口的行
仍按需读取，折叠和事件可见性仍在 Text 中计算；索引被释放并重新载入时会重新计算筛选。

同一份离线 `ping3`，查询 `func:.* AND duration:>0` 命中 58,535 行。Chromium 1500×900
每版交错测量七次，从跳转开始到定位目标行的中位数，常速 **137.0 → 114.6 ms**，4× CPU
降速 **544.7 → 463.3 ms**。每次省去一次索引扫描和一次筛选通知，仍仅挂载 160 行，返回后
保留原切片。此计时不是屏幕呈现时间。见 `build/benchmarks/20261121-filter-handoff/`。

### 深跳转不再先绘制旧窗口

Windowed Text 已打开、目标行尚未挂载时，从 Timeline 跳转会暂时隐藏旧行和旧任务标题，
底部显示 `Locating L…`，不改变顶栏高度。成功后直接显示目标窗口；失败恢复原窗口并说明
原因；点顶部返回可以取消等待。首次打开 Text 仍显示原有加载进度，已挂载的目标不显示等待提示。

如果这个窗口读取超过约 300 ms，已校验的新行计数直接出现在底部固定的 `Locating L…` 提示中，
不会在滚出视口的正文状态栏重复播报。提示可在窄屏换行，不改变工具栏和正文的位置；完成、失败或
取消时不保留旧计数。离线 `ping3` 从深处 `L63550` 跳至 `L82255` 的受控慢读中，1500×900、
844×390、390×420 和 240×360 四种视口都可见计数，也能点按返回保留原切片。排序窗口释放首批
读取后显示 `9 / 160`，未改变滚动位置。记录见 `build/benchmarks/20261121-deep-jump-progress/`。

`ping3` 在 Chromium 4× CPU 降速下，以相反顺序做两轮前后对照（每次六跳），高亮前的
绘制耗时中位数在 1500×900 从 **13.1–29.4 ms** 降到 **3.8–4.7 ms**，在 844×390 从
**12.4–20.3 ms** 降到 **1.8–2.9 ms**。目标行位置和焦点一致，但未测到稳定的端到端提速。
240 和 320 px 宽的触屏模拟均可点按 44 px 高的返回按钮。记录在
`build/benchmarks/warm-deep-jump/`。

已打开的 Windowed Text 跳到尚未挂载的行时，由 Timeline 在目标窗口提交后统一定位并高亮；
滚动前按工具栏吸顶后的高度计算目标位置。首次打开、已挂载行和普通 Text 导航不走这条路径。
同一份离线 `ping3` 在 1500×900 桌面和 844×390 触屏、Chromium 4× CPU 降速下做两轮反序对照，
每版共 24 跳：目标行每跳垂直定位从两次降为一次，消除了从页首深跳时的 29 px 二次位移。
最终行的位置、横向滚动、焦点和返回的切片一致；点击到高亮及后续帧回调的耗时未稳定下降。
原始对照记录见 `build/benchmarks/warm-deep-jump/single-*/`。

首次打开 Windowed Text 也按工具栏吸顶后的高度定位。最终高亮仍会核对位置，若布局没变，
不足 1 px 的偏差不再触发滚动；若位置已变，仍可校正。真实 `ping3` 以时间顺序和任务分组
各跳两个目标、覆盖四种视口：16 次首跳原有的 29–39 px 二次位移全部消失，最终位置、
焦点和返回的切片不变。Chromium 4× CPU 降速下，每版 9 次交错首跳至 `L82255`，
高亮时间中位数 **652.3 → 637.5 ms**；主要收益是去掉二次跳动，不将这组耗时视作普遍保证。
原始记录见 `build/benchmarks/20261121-text-cold-placement/`。

### 窄屏 Text 工具栏

启用紧凑触控布局且窗口模式切换可见时，**In Timeline** 的行号后缀可以省略，主文案与
完整的无障碍名称保留。极窄窗口仍可自然换行，不缩小触控目标。带活动筛选的 `ping3` 在
361 和 365 px 宽度下不再多占一行，正文多出 47 px 高度。57 组桌面和触屏视口对照中，
工具栏主按钮及返回按钮的中心均可命中。记录见 `build/benchmarks/20261121-text-toolbar/`。

桌面窗口高度不超过 400 CSS px 时复用紧凑工具栏，避免内联筛选区和按钮换行占满正文。
带筛选的 `ping3` 在 320×320 下，工具栏底边以下的空间从约 0 增至 235 px；844×320 下
从 129 增至 235 px。窗口变高时恢复桌面的内联工具栏；正在编辑的查询保留草稿、焦点和选区，
不会自动应用或修改已保存的面板显隐偏好。对照见 `build/benchmarks/20261121-text-short-desktop/`。

目标窗口提交时先恢复行和任务标题的可见性，再测量行高，避免聚焦时重新计算整组行的样式。
仍以相同的 `ping3`、视口与降速设置做两轮反序对照：高亮前样式重算及布局的中位数，桌面从
**79–84 ms** 降至 **70–73 ms**，触屏模拟从 **71–74 ms** 降至 **59–65 ms**。聚焦所在阶段的
样式重算及布局从约 **13–14 ms** 降至 **1–2 ms**。最终行位置、横向滚动、焦点与返回的切片
一致。桌面点击到高亮未稳定缩短；这些计时也不是屏幕呈现时间。对照记录见
`build/benchmarks/warm-deep-jump/layout-summary.txt`。

离开 Timeline 之前把旧窗口切为等高占位；支持 `content-visibility` 和固有块尺寸的浏览器
不再排版旧行，等待时也不测量、绘制折叠引导线。成功时绘制目标窗口的引导线；失败则恢复旧窗口
及引导线；取消不保留占位状态。与上一步的版本做两轮反序对照后，视图切换和标签聚焦中的
样式计算及布局中位数从 **16–17 ms** 降到 **3–5 ms**。点击到高亮中位数在桌面从 **163–164 ms**
降到 **136–139 ms**，触屏模拟从 **142–146 ms** 降到 **121–124 ms**。目标位置、焦点和返回切片
一致。测量沿用同一 `ping3` 及 Chromium 4× CPU 降速，不是屏幕呈现时间。见
`build/benchmarks/warm-deep-jump/paused-guides-summary.txt`。

### 源码链接不再逐条注册事件

函数名源码链接保留原生链接行为，不再带内联点击处理器。Text 已有的行点击和双击处理
忽略这些链接，因此鼠标、Enter 和触屏打开源码都不会展开当前行；Alt+点击仍跳到 Timeline。

在 Chromium 145 中打开 `ping3` 的 Full Text 再回到 Timeline，保留 82,529 行和
57,676 个源码链接；浏览器报告的事件监听器由 **57,832 降到 156**。链接文字、地址、
提示和目标一致；Timeline 数据仅生成耗时字段不同。对同一组 40 个不同切片，点击到
两帧回调的中位数前后均约 29 ms，两次均未记录到主线程长任务。这减少了浏览器持有的
监听器，不代表 DOM 规模缩小或切片点击变快。对照日志在 `build/benchmarks/20261119-trace-jump/`。
