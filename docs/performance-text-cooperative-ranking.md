# Text 协作式耗时排序 / Cooperative duration ranking（2026-11-13）

优化**显式启用的实验性 Windowed Text** 冷耗时排序的主线程响应性。
重新生成分块 sidecar 后，选择 **Windowed Text** 或在 HTTP URL 加
`?text=windowed`。默认完整 renderer、sidecar 阈值、版本及 Timeline 不变。
用法与完整文档回退见[窗口化说明](performance-text-window.md)。

## 实现与准确性

[数字位置排序](performance-text-duration-ranking.md)避免了每行一个短期对象，
但 371,997 行的冷排序与完整重建仍有约 180–200 ms 同步前缀。本次不增加
Worker/Blob/CSP 依赖，不只排序当前窗口，也不牺牲完整记录验证来缩短任务。

- 当前 plan/方向缓存未命中且记录数 **>16,384** 时使用协作式路径；小输入仍用
  同步数字 Array 排序。缓存仍只保留一个 plan/方向，不新增跨操作缓存。
- 按完整 time/task plan 提取精确耗时，保持
  `parseFloat(sort-duration || duration || '0')` 的回退及精度。
- 1024 项 typed-array 位置段分别稳定排序，再自底向上稳定归并；相等时优先左项，
  升降序都保持原 plan 的同值顺序。最终恢复原始行号及 ordinal，大行号不截断。
- 每 2048 项或一段结束 yield，runner 约 **8 ms** 后用 `setTimeout(0)` 让出
  事件循环。一次步进和原生小段排序不是硬时限，不承诺每帧或任意机器的预算。
- NaN/Infinity 等非有限值仍回退到原对象比较器，不擅自归零、丢弃或指定新位置；
  该回退仍同步阻塞，不能将有限值路径的响应性结论套用到异常输入。

原始行、源码 ID（包括 0）、函数参数、返回值、地址、调用关系和 plan 不修改。
完整排列先经 navigation 校验，再发布缓存；既有 160 个挂载单元预算、分组读取、
资源 LRU、完整绘制块校验和默认完整 DOM 路径不变。

## 操作、取消和失败

准备时显示进度及 `aria-busy`，保留旧 DOM、完整导航顺序及计数。只有完整结果
可发布。新显式重建、改变宽度、离开 Text 或 Full Text 会取消旧排序；过期进度
和迟到结果不能覆盖当前窗口。返回同宽 Text 时也会重新应用未完成的请求。
滚动及 ResizeObserver 不抢占正在准备的显式重建。
隐藏 Text 时忽略全局 resize 事件，避免后台重启已取消的排序；视图显式恢复时
再按当前宽度和未完成状态重建。

跳行等待最新排序，自己的 AbortSignal 只取消导航等待；方向连续改变时跟随最新
排列。排序失败保留旧窗口并提供 **Retry**。Full Text 仍是完整文档回退，成功后
迟到排序不可重新挂载窗口；失败会显示错误，并允许重试排序或 Full Text。

不新增 Cancel 按钮或 Escape 排序语义。过滤器保留原有完整扫描/失败回滚路径，
不据此宣称新增了完全原子的筛选事务。

## 内存和剩余阻塞

有限值协作路径的临时 typed buffers 为 **`16 × N` 字节**：精确耗时 8N、两份
位置缓冲区各 4N。本轮两规模分别约 **1.10 MiB / 5.68 MiB**。输出行号 Array、
ordinal 数组、模型、导航状态、DOM 和资源缓存另计；不要求立即 GC，不宣称
总内存有界或比同步路径更省。非有限值回退在分配两个位置缓冲区前发生，仍有
8N 耗时及旧对象成本。

time/task plan 准备、完整导航验证、visibility/geometry 重建和 DOM 解析仍有同步
阶段。让出主线程可能增加 wall time；不能把同步前缀下降当成整个操作更快。

## 对照方法

基线 **`642dcee1dad5`**。前后 sidecar 使用同一份不可变资源，只替换两个 Text
runtime，入口文件独立 inode。使用真实 trace、独立 Chromium、1440×900、
`fgview` HTTP、显式窗口模式，三轮交替 before/after、after/before、before/after。
测量时不并行测试/构建或运行 profiler。无 vmlinux/DWARF，不外推为源码丰富报告。

每步比较完整模型、完整可见行/导航顺序/计数摘要。记录同步前缀、API 就绪、两次
rAF 反馈代理、Long Tasks 及 API 期间 rAF 回调次数。observer 注册后先让出一项
任务再开始操作，避免丢失当前任务的阻塞；回调次数不是 FPS，零 Long Tasks
也不是任意帧/任务有界的证明。
