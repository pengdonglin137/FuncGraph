2026-11-12 后续更新（离屏布局）：新分块 sidecar Text 在浏览器能力满足时使用原生 `content-visibility: auto`，按当前可见行维护各绘制块的离屏尺寸估算，选中/聚焦块和展开源码保留正常布局。计数变化或窄/宽屏切换会清除已访问块的旧尺寸，避免过滤/折叠后保留空白高度；Text 隐藏时切换断点同样覆盖。跨块远跳立即滚动，附近保留平滑动画；旧锚点延迟滚动会核对当前目标及视图。打印/不支持浏览器仍完整布局。过滤、调用树、排序、源码及导航保持完整模型；全部 DOM 仍创建并挂载，未交付 DOM/模型有界窗口化，不能据此关闭第二阶段。细节及测量见[设计记录](../design.md#text-浏览器级离屏布局2026-11-12)。

2026-11-11 后续更新（源码缓存）：sidecar 源码资源已增加 LRU，最多 8 块、合计不超过 16 MiB 的已校验 UTF-8 JSON 字节数。实际读取/加载刷新顺序，ready 探测不刷新；淘汰后可重新下载和校验，不删除已展示源码。单块超限仍完整交付但不保留，内嵌/旧版完整池及普通数据缓存不变。共享请求、取消和 Retry 继续有效。该预算不是 JS heap、并发工作或完整报告内存上限；Text 网络分块/窗口化、Worker 及模型/DOM 有界缓存仍待完成。以下早期“源码无 LRU”描述是原阶段记录，当前策略详见设计 §8.10 和中英文查看器指南。

2026-11-11 后续更新：**sidecar 源码按需分块已实现**。`fgSourceChunks` 内嵌 version/count/chunk_size；源码 ID 按最多 64 条记录分为 `source-<首个ID>.json`，manifest 标记 `sources=chunks-v1`。精简 `fgSrcLines` 仍内嵌。展开时只读对应块，同块消费者共享请求及大小/SHA-256 校验；取消最后一个消费者才中止共享下载。收起/关闭/替换详情和离开视图取消等待，迟到结果不填充旧节点，返回视图恢复仍展开的未完成面板。失败有 Retry；源码布局按钮等待异步填充完成后安装，闭合的 Timeline 源码详情不提前读取。紧凑悬停位置无源码请求，未知旧位置可异步回退。默认 single 及 auto 未超阈值的离线输出不改存储模式。以下早期“源码内嵌/分块未实现”描述为原阶段记录；本轮只完成源码交付，不包含 Text 网络分块/窗口化、Worker、源码 LRU 或字节上限，单条大源码仍完整保留，缓存仍可累积。

2026-11-10 更新：显式 `--timeline --report-mode sidecar --output REPORT_DIRECTORY` 和可选 `--report-mode auto --sidecar-threshold BYTES` 已实现，使用 `fgview REPORT_DIRECTORY` 打开。默认单文件不变，没有默认阈值；auto 必须显式指定完整 HTML 字节数阈值，只有严格超过才 sidecar，否则在同一目录生成可离线打开的 index.html。Timeline 首屏不请求 Text/Compare/过滤索引，也不创建逐行 Text DOM；统一过滤按需读取完整 `text-index.json`，不挂载 Text。Text 在首次访问或行号/锚点跳转时**完整加载**，重新应用当前过滤并释放索引缓存，随后保留 DOM。源码仍内嵌；Text 虚拟化、源码分块/LRU 仍未实现。详见 [查看器指南](../viewer.cn.md)。

源码前置解耦已完成：`fgSrcLines` 保存真实行号 → source ID，Timeline 从共享 `fgData` / `fgSrc` 查调用点，不再要求对应 Text 行或占位 DOM 已挂载；源码块按完整函数标识缓存。可选 `--timeline --no-text-view --keep-source` 保留完整源码池及 inline，同时省略逐调用 Text DOM，默认轻量模式不变。源码池/索引仍完整内嵌、首次使用时同步解析，尚无外部源码分块或 LRU。

调用点悬停进一步改用现有 `sources.callers` 紧凑位置链，选择最内层位置；已解析或明确不可用的调用点不再为展示一行路径而解析整个源码池/行映射或临时源码 DOM。空链表示本报告无可用位置，缺 key/未支持表示保留旧 HTML 回退；源码详情仍使用原有完整内嵌池。此改动只是消除悬停对源码 HTML 的同步依赖，不代表已完成源码按块交付或缓存淘汰。

用户随后提出按 trace 行数判断是否启用 sidecar。行数方案保留为后续候选，尚未接入 CLI；本次实现原方案的显式最终 HTML 字节阈值，不擅自确定行数/字节默认值。原因是同样行数的 Text、源码池和内嵌数据大小可能不同；字节阈值可以严格保证小于/等于设定大小时不启用 sidecar。包装脚本 single 模式原有 15 万行省略 Text 的规则仍独立存在，auto/sidecar 不自动省略 Text。

状态：第一阶段显式 sidecar 及显式字节阈值自动分流已完成。新生成且超过 4,096 条记录的 sidecar Text 已支持网络分块与独立 4 块 / 16 MiB 已校验字节 LRU，准备仍是 deferred-full，而非虚拟列表。不改变默认输出或已有 single 命令；auto 是可选模式，目录入口固定，未超限报告保留完整离线 HTML。4,096 条只是 sidecar 内部的传输分块规则，不是启用 sidecar 的新阈值。现有 `--no-text-view` 语义不变。

72,176 条真实记录、三对交替测量：首批已解析进度的 rAF 反馈中位数 948.6 → 74.2 ms，但完整 Text 双 rAF 就绪 7,119.7 → 7,378.9 ms（增加约 3.6%），最长长任务 3,320 → 3,402 ms，采样 RSS 未改善。全部 Text 字节、完整索引和模型一致；这只是传输/反馈及后续窗口化的基础，不是大 trace 首开或布局优化完成。测量条件、边界、复现及 789 项回归结果见 [设计记录](../design.md#text-网络分块与有界资源缓存2026-11-11)。

Text 完整挂载的准备阶段已改为协作解析：旧/小报告先校验完整 `text.html`；新大报告逐个下载、校验、解析最多 4,096 条记录的 HTML 网络块，每块包含完整的 512 行绘制块。都在文档外累计节点，显示进度并允许返回/切标签/Escape 取消；只有全部记录与元数据完成才挂载。取消丢弃未挂载节点，新分块路径仅复用仍在有界缓存内的资源，已淘汰的块重读；旧单资源路径保留原有完整 HTML 缓存行为。最终挂载前先给予 **Finishing Text layout…** 绘制机会，再恢复排序、折叠、源码、过滤和导航；半初始化失败仍需重载。最终初始化/样式/布局、单个复杂块和 GC 仍可能阻塞，总时间不保证缩短。网络分块已落地，但不是虚拟列表或完整报告有界内存，第二阶段仍只部分完成。

当前产物为 `index.html`、`.funcgraph-sidecar` 和 `data-<32位report-id>/`，后者含带精确字节数/SHA-256 的 manifest、Timeline、可选 Compare、`text-index.json`，以及完整 `text.html` 或按原始记录序号命名的 `text-<first>.html`。分块路径不重复保存整份 `text.html`。同级暂存、先发布不可变资源、最后原子替换入口；拒绝非空未托管目录。更新保留旧版本，避免已打开页面读错资源，也意味着需要手工管理磁盘占用。故障时保留旧入口；网络错误可重试，Text 半初始化失败要求重新加载，避免复用旧监听器。Text HTML 资源及过滤索引在挂载后从 `fgData` 缓存释放，但完整 DOM 不淘汰。

2026-11-11 的后续实现把完整记录快照、校验和折叠元数据纳入上述协作准备：节点仍在文档外时逐批构建，最终挂载时才发布根模型。已准备索引可复用，没有索引则读取已解析的完整行，不新增索引请求。取消关闭嵌套生成器，不缓存部分折叠事实；挂载前元数据失败可重试，最终初始化失败仍需重载。首个折叠不再承担这份建模工作，但总准备时间可能增加，完整 DOM/同步布局和逐次元数据扫描仍未消除。下一步仍是模型驱动导航、真正的视口窗口化与源码分块，不把预备元数据标为第二阶段完成。

导航的后续解耦已接入完整数字行号、源码展开能力、可见性和展示排列索引：候选刷新不再从已挂载行反推完整结果，点击/锚点按身份定位，键盘按当前顺序二分查找最近可见调用；排序后保留选中行身份。后端现以 version-2 Text 索引逐行交付准确 source ID，保留 `0`、复用 ID 和明确不可展开的 `null`，由同一次源码池分配同时生成 HTML/源码行映射/索引。导航可以只读完整记录；已有索引直接复用，否则在完整行快照时一并采集能力，不为打开 Text 新增索引请求。version-1 仍可读，未知能力保留 DOM 回退；取消不发布部分模型/排列。真正窗口化仍需在目标未挂载时加载/呈现目标行，不能因逻辑目标已脱离 DOM 就宣称已实现按块交付、视口 DOM 上限、完整导航窗口化或有界内存。

## 问题与目标

用户提出：HTML 达到一定规模后切换到 sidecar，并按需加载。

真实 traceB 有 72176 行、55186 个真实调用，完整报告约 114.7 MB、103.5 万 DOM 元素。首次 Text → Timeline 的诊断中，JSON.parse 约 5ms，样式更新约 115ms，GC 的 DOM embedder tracing 约 174ms。诊断 profile 有额外开销，不能替代无干扰基准，但说明只外置 Timeline JSON 并不能消除巨大 Text DOM 的负担。

CLI 使用 `HtmlGenerator.iter_sections()` / `ReportSpool`：逐行写临时文件、准确统计假想单文件的完整 UTF-8 字节数，再有界提取 sidecar 资源；不改变完整 trace 的解析/符号解析成本。旧的 `generate_html()` 字符串 API 保留。源码池/索引仍内嵌，Timeline/Compare 在显式 sidecar 或 auto 超限时外置。统一过滤已脱离逐行 DOM，使用完整行文本及共享结构属性索引；Text 折叠、键盘导航和跳转仍需先全量挂载，保持完整语义。

目标不是把一个大文件换成几个同时加载的大文件，而是：首屏不传输、不解析、不创建未使用的内容；已访问内容复用缓存；不牺牲完整 trace 语义。

## 后续分块/虚拟化产物提案（尚未实现）

```text
report/
  index.html              轻量 UI 外壳、首屏概要、report ID 和 manifest 地址
  manifest.json           schema 版本、能力、数量、资源索引、大小和校验信息
  timeline.json           第一阶段仍保留完整 Timeline 模型输入
  compare.json            仅进入 Compare 时加载
  text/index.json         行号、调用树、块范围、过滤/定位所需的紧凑元数据
  text/00000.json         按块保存文本行及其结构化属性
  sources/index.json      源码 ID 到资源块的映射
  sources/00000.json      按展开/调用点请求读取的源码内容
```

布局为提案，不代表当前 CLI 已支持这些路径。

| 访问操作 | 加载/渲染边界 |
|---|---|
| 打开报告 | 只读外壳、manifest 和概要；大报告默认 Timeline |
| 首次进入 Timeline | 获取 Timeline 数据并构建模型，不创建全部文本 DOM |
| 切到 Text 或定位某行 | 先读元数据，定位所需块，只挂载可见窗口及少量缓冲行 |
| 展开源码/查看调用点 | 根据 source ID 读取对应源码块，而非解析整份源码池 |
| 进入 Compare | 独立读取 Compare 数据；不为未访问标签加载资源 |
| 再次访问 | 复用完整模型和有上限的块缓存，不重复请求或无限累积 DOM |

第一阶段 Timeline 可以仍完整读取，其后再按测量结果考虑分轨道/时间段存储或可转移 typed arrays。不能直接按任意调用数切开调用树：跨块父子、inline/ghost、off-CPU、未闭合等待、错误链和统一过滤均需要明确的全局身份与边界。

## 输出模式与打开方式

- 保留默认单文件模式，继续支持离线双击和单附件传递。
- 当前已提供 `--report-mode single|sidecar|auto`，默认 single。Auto 必须显式指定 `--sidecar-threshold BYTES`；无默认阈值，0 对非空报告强制 sidecar。sidecar/auto 均需 Timeline 和独立目录，auto 的两种结果固定为该目录的 index.html，便于反复生成及安全切换；显式 sidecar 不代表开启自动分流。
- 自动分流依据是**如果按单文件完整生成**、包含文本、源码池、内嵌数据及资源时的 HTML 未压缩 UTF-8 字节数，不是 sidecar 外壳大小、原始 trace 文件体积、行数、Timeline JSON 大小或预计 DOM 数。行数/DOM 数只作诊断，不单独触发 sidecar。通过计数字节的输出阶段判断，避免只为选模式在内存拼出巨型字符串；保守上界只能用于筛选是否需要精确计数，不能因高估而让未超限报告进入 sidecar。阈值做成可配置项，默认值由实测确定，不能挪用当前分阶段准备的 1 MiB JSON 阈值。
- 本地只读 HTTP 查看器为 `fgview`：只绑定 `127.0.0.1`、默认空闲端口；单文件模式不提供兄弟文件，目录模式需独立报告目录。没有目录列表/写接口，不跟随内部符号链接，无新依赖。导出及 auto 判断由 CLI 完成，不由查看器完成；Text 虚拟化仍待实现。`fgreport --open` 对目录模式在前台运行 fgview，Ctrl+C 结束。
- 页面通过 `file://` 打开时给出明确启动指引，不能假定浏览器允许跨本地文件 fetch。服务器关闭或资源缺失时显示可重试错误，不能永久停在 loading。
- 归档/共享 sidecar 时打包整个目录，不再承诺单个 index.html 独立可用。

后续诊断确认完整 Text 的最终同步成本主要包含原生聚焦触发的全量样式/布局，不只是 JS 函数耗时。已修正原生焦点越过“不滚动”约定及窄窗口工具栏遮挡，并在 Text 基准中记录独立 script/style/layout 计数；完整布局成本和 DOM 内存尚未解决。直接 `content-visibility:auto` 占位原型改变了纵向尺寸和横向滚动范围，未交付，也不能据此勾选第二阶段；诊断与约束见设计文档的 Text 焦点与滚动边界。

完整过滤记录模型现已在两条路径共用：索引侧准备稳定的非 DOM 记录；挂载 Text 时复用已有模型，或在首次实际查询时快照全部原始行并按行号恢复模型顺序。过滤只计算行号集合，展示层再投影，移除全部 Text 行后仍可完整匹配；模型不会把折叠摘要当作原始 trace。`fgData` 输入释放后，查询模型仍保留记录且完整 DOM 常驻。这个步骤只解耦了匹配数据；折叠、任务/耗时排列投影、键盘/锚点和源码还依赖 DOM，第二阶段的分块/虚拟化/LRU 仍未完成。

## 必须先解耦的接口

早期折叠测量确认普通冷首击回退。完整折叠元数据现已纳入协作 Text 准备，保留取消和完整发布约定，数字行号导航也已解耦；范围索引最终编码同样分阶段让出执行机会。新增索引仍增加准备成本，不能靠搬走首击工作就声称首开或每次点击更快。真正的 Text 分块/窗口化仍待推进。

折叠现已进一步拆出纯记录模型：成员关系、入口/出口配对、完整后代调用计数，以及过滤与折叠共同决定的可见性均可脱离 DOM 求值。成员按原始记录序号压缩为精确的共享 Uint32 范围索引，不用最小/最大行号包络任务交错的空隙。普通成员查询不再扫描完整记录；深度/递归/保存状态恢复先修改全部状态，只投影实际变化范围的去重并集。过滤或 Clear 不得打开折叠祖先，展开也不得泄漏过滤拒绝的行/源码。摘要格式和深度属性仍依赖已挂载 DOM，导航候选重建仍扫描完整数字元数据，缓存与完整 DOM 仍占内存；这不是第二阶段窗口化完成的证明。72,176 行真实 trace 的递归投影由全量行降至目标子树 90 行；准备代价、慢样本和复现方法见设计文档的“折叠范围索引与局部投影”。

1. **数据提供者**：Timeline 输入、源码查找、行元数据、文本块独立于 DOM。单文件实现读取内嵌数据，sidecar 实现按资源读取；分析算法不关心存储格式。
2. **Text 视图**：过滤/折叠/调用树导航不能再枚举已挂载 DOM 当作完整 trace。先在结构化数据/索引计算结果，再映射为可见行；搜索与 CSV 必须覆盖未加载块。
3. **Timeline → Text/源码**：通过真实行号和 source ID 定位，不能要求 `L<n>` 元素或 `data-src` 预先存在。`#L<n>` 锚点应加载正确块并恢复行定位。
4. **生命周期**：统一异步 ready/error/cancel；重复请求共享 Promise，切换取消使用 AbortController/请求代数并丢弃过期结果。完整模型才缓存，块缓存有容量上限。
5. **输出一致性**：manifest 中的 schema、report ID、资源大小/校验防止混用旧数据；临时目录写完整后再发布，失败不破坏原报告，也不留下看似完整的半成品。

Worker 是独立的第二步：仅 fetch JSON 不会把 JSON 解析和模型准备自动移出主线程。可在消除巨大常驻 Text DOM 后重新 profile，决定哪些纯模型阶段值得迁移；不把大量结构化对象往返复制当成免费操作。
