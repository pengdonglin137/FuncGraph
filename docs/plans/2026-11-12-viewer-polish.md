# 页面美观性与易用性：下一轮设计

状态（2026-11-12）：已落地详情语义配色、参数整项换行，以及主信息优先 / Trace metadata
按需展开，以及筛选草稿 / 应用反馈。阅读方式见 [detail-layout.md](../detail-layout.md)
和 [filtering.md](../filtering.md)。其余 P1 仍为待实施的设计建议。

## 目标与边界

优先减少寻找信息、理解状态和执行操作的成本，而不是增加装饰。
技术准确性、原始数据可核对、大 trace 性能不退化，是所有视觉调整的前提。
延续现有字体、明暗主题和低饱和配色，不另加 UI 框架、渐变卡片或更多常驻按钮。

已具备的 Tools 分组菜单、全屏、详情扩展、调用栈源码列及用户/内核分界线应继续复用，
不作为待开发的新功能。详情语义配色见 [detail-colors.md](../detail-colors.md)。

## P0：详情的信息层级

- 顶层先回答“选中了哪个函数、属于哪个空间、有没有需要注意的状态”。函数符号最突出，
  模块和次要状态靠后；告警不能只依赖颜色。
- 常用信息以稳定顺序出现：耗时与 self、调用位置、参数、返回值。避免被原始地址、
  长说明和导出入口打断；未记录或不适用的项目明确说明，不用占位零值。
- 原始字节、类型修正规则和来源说明按需展开，保留可核查入口。仅调整默认阅读层级，
  不删除信息，也不把未知值包装成已解析值。
- 小屏参数优先按完整 `name=value` 单元换行，避免长十六进制值被拆成孤立的一两个字符；
  超长值仍允许换行与完整复制，不能只为整齐而截断真实数据。
- 保留 CALL STACK 的无缩进对齐、独立源码列和边界线；当前帧有清晰但轻量的强调。
  内联、未采集和真实调用帧继续保留文字区分。
- 宽屏保留并排阅读的可能，小屏改为纵向顺序。不要让多个粘性标题叠加后吞掉内容区。

验收：在真实混合 trace 中，能迅速找到当前函数的参数/返回值、调用位置及其来源；
长函数名、长路径、缺失源码、深调用栈不破坏对齐，原始数据仍可访问。

## P1：统一操作入口与可点击反馈

- 现有搜索、视野恢复与全屏属于高频操作；分析、显示、导出继续放在 Tools 的分组中，
  不重新平铺。先统一文案、图标与分组顺序，再考虑增加入口。
- 详情中的“切换所选调用”“移动视野”“打开源码”“跳到 Text”应有不同且一致的文案，
  避免把不同动作都叫作 Open 或 Show；不重复增加 Parent/First child 的同义按钮。
- 分布分析、导出等次要动作不抢占函数标题的第一视觉层，尤其避免小屏标题被多个跳转
  链接撑成多行；保留可发现的入口，不改成只能通过 hover 才能操作。
- 源码路径只有可操作时才使用链接外观；悬停与键盘焦点同样清晰，触屏不依赖 hover。
  省略路径时保留行号，完整路径仍可核对。
- 统一按钮高度、圆角、边框和焦点轮廓。高频触屏目标维持足够点击区域，但不要扩大
  每个文本行的高度，导致调用栈与可视区过度稀疏。

验收：键盘能完成主要流程；菜单、源码链接和关闭操作在深色、浅色与触屏下均能辨认；
禁用、不可用与“没有记录”不混为同一种状态。

## P1：空状态、反馈与布局节奏

- 区分“trace 没有此数据”“过滤后没有结果”“数据仍在加载”和“解析失败”。
  给出针对性的下一步，例如清除过滤、调整采集选项或查看错误，而非一律显示空白。
- 使用少量统一的间距和分隔线组织标题、数值、参数、源码、调用栈，减少重叠边框。
  耗时等指标保持正常前景色，辅助文字要淡但仍清晰。
- 搜索无结果、过滤生效、全屏和详情展开的状态应在相关入口附近体现，不新增整排提示。
- 大量数据准备阶段继续提供阶段反馈并让出主线程；视觉优化不能增加全量 DOM、
  全量 trace 扫描，或仅为了展示颜色就触发额外符号和源码解析。

## 验证顺序

1. 用现有真实 kernel sample、mixed sample 与 pigz/zlib 案例审阅设计，不改写旧采集元数据。
2. 覆盖用户态、内核态、混合、缺失参数/源码、错误链、内联和截断场景。
3. 检查明暗主题、宽屏、窄屏、横屏短窗口、全屏与详情扩展；单 HTML 和 sidecar 都覆盖。
4. 验证键盘焦点、链接、复制文本、长符号/路径、HTML 转义及文本对比度。
5. 比较调用选择、时间范围、过滤、导出和原始记录，保证视觉调整不改变数据含义。
6. 每轮只实现一个可独立验证的小改进，附截图和回归结果，再推进下一项。
