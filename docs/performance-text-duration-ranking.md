# Text 耗时排序 / Numeric duration ranks（2026-11-13）

优化**显式启用的实验性 Windowed Text** 首次及切换方向/模式时的耗时排序。
重新生成分块 sidecar 后，选择 **Windowed Text** 或对 HTTP 报告使用
`?text=windowed`。默认完整 renderer、自动分流阈值、版本和 Timeline 外观不变。
操作入口、完整文档回退和限制见[窗口化说明](performance-text-window.md)。

## 问题与实现

[完整导航批量更新](performance-text-navigation-visibility.md)后，当前版本 CPU
profile 仍发现冷耗时重排会创建大量短期对象，并有较多 GC；分散 DOM 解析也仍慢。
Profile 只用于选择热点。独立原型比较完整 371,997 行的对象排序、数字 Array 和
typed-array 位置排序，所有完整结果相同；数字 Array 在本轮四种 plan/方向组合中
较快，正式测量不使用 profiler 或原型替代完整页面操作。

- 有限耗时先按完整 time/task plan 读取一次，保存为临时 `Float64Array(N)`。
  稳定排序数字位置，不再为每行创建 `{number, ordinal, duration}` 对象。
- 分别从排序位置恢复原始行号和 ordinal。稀疏大行号不截断到 32 位；同值项在
  升降序中均保持各自原 plan 顺序，不使用整列 reverse 破坏相同耗时的稳定性。
- 保留 `parseFloat(sort-duration || duration || '0')` 的精度、零值、缺失和回退
  行为，不把显示层四舍五入的耗时替代精确排序字段。
- NaN/Infinity 等非有限结果回退到旧对象排序和原比较器，不擅自丢弃、归零或
  强行为 NaN 指定新的位置；该路径仍创建对象。无效方向在修改任何数据前拒绝。
- 仍只缓存当前一份 plan/方向排列；筛选和折叠不改变键时复用，切换方向/模式
  仍重算。默认完整 DOM 路径未切换，完整导航验证不弱化。

原始记录、源码 ID（含 0）、参数、返回值、父子关系和排序 plan 不修改。已有
160 单元挂载预算、资源分组/LRU、512 行完整解析校验、取消/重试及 Full Text
回退不变。性能优化不跳过未显示行的验证。

## 内存与边界

每次缓存未命中时，临时精确耗时数组为 **`8 × N` 字节**：本轮两种规模约
**563.9 KiB / 2.84 MiB**。另有 `N` 个数字位置的 JS Array，其字节数依引擎而变；
既有输出行号 Array、ordinal typed array、模型、导航状态、折叠掩码和资源缓存
另计。没有新增跨操作缓存，不要求立即 GC，也不把“避免 N 个临时对象”当作
浏览器总内存下降的实测结论。非有限值回退额外保留旧对象成本。

原生排序与全量模型重建仍同步；网络读取、DOM 解析/布局和 GC 也未被消除。
目标是减少冷排序的工作，不承诺所有操作更快、每帧有界或任意大输入无卡顿。

## 回归与复现

四个模型回归覆盖 v1/v2/v3/v4、time/task、升降序、完整行号/ordinal 对照，稀疏
超大行号、空/单行/全同值、原文和源码 ID 不变。有限值路径只排序数字且每个字段
按原回退规则读取一次；80 组确定性非有限值数组对照旧对象排序。Chromium 再覆盖
八种有限/非有限、plan/方向组合。缓存回归按真实 rank-helper 调用计数，不再依赖
旧排序对象的形状；完整 90 组合折叠/筛选/排列 reference 保留。

```bash
python3 funcgraph.py TRACE --no-config --timeline --enable-fold --filter \
  --func-links --report-mode sidecar --output REPORT_DIRECTORY
PYTHONPATH=.:tests python3 tests/benchmark_text_rebuild.py BEFORE_DIR AFTER_DIR \
  --trace TRACE --rounds 3 --scattered --folded --bidirectional \
  --output duration-ranking-benchmark.json
PYTHONPATH=.:tests python3 -m unittest -v test_textmodel test_textwindow
```

`--bidirectional` 是基准脚本选项，不是用户 CLI 默认值；在原操作序列中增加升序
和再次降序重排，不改变旧的默认基准序列。单次排序缓存未命中不等于网络缓存也
完全冷；窗口仍按原锚点定位，不能把切换到的可见窗口当作全部原始记录。

本机证据保留在 `build/benchmarks/20261113-text-duration-ranking/`，包含原型、profile、
正式轮次、完整语义摘要、测试和打包验证。旧阶段证据不修改，不自动发布。
