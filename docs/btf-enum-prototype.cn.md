# BTF 枚举名与函数原型：Timeline 详情设计

## 默认显示

```text
▸ 函数原型 · BTF
参数    mode = TX_FAST (1) [2 个同值名中的首项 ▸]    flags = 0x0
返回    TX_BUSY (−1)
```

示例中返回值是唯一匹配。原型展开后，显示可复制的多行 C 风格声明与来源，例如：

```c
enum tx_status submit(
    enum tx_mode mode,
    unsigned int flags
);
```

**Function prototype · BTF** 通过详情标题中函数名旁的箭头展开，即使本次没采到参数也可查看。默认折叠且不占用字段区；同一函数的界面刷新保留开合状态，切到另一函数时默认折叠。展开后长声明在标题下使用详情窗全宽，自然换行，不打断记录字段。原始符号可从 **Actions → Show recorded symbol** 查看，没有原型时标题箭头仍用于查看原始符号。别名及原型可用键盘展开，不依赖悬停。Raw argument slots 和 Original return bits 保持独立。

窄屏或短分栏中，若只滚动详情窗仍放不下标题和展开内容的首行，直接展开原型、枚举或原始值时会临时使用图表区域阅读。页头保留 **Restore chart and detail split**；恢复后仍是原切片、时间范围和分栏尺寸，已展开的内容不会收起。空间足够时只滚动详情，不隐藏图表。

在紧凑布局中，用 **Actions → Show function prototype / Show recorded arguments / Show recorded return value** 直达有内容的字段。详情分栏低于 140 CSS 像素时，暂用图表空间显示声明和复制按钮，或显示值及其摘要；参数与返回值的候选名和原始记录仍按需展开。点 **← Call details** 恢复原分栏、滚动位置和 Actions 焦点。
展开原型或候选后，区块末尾也有 **← Call details**。焦点在跳转区块内时可按 `Esc` 返回，不取消当前切片选择；在筛选输入框内保留原来的按键行为。

别名和原始值的展开区按详情窗宽度排版：详情窗不超过 640 CSS px 时，即使主窗口是横屏宽窗口，展开内容也使用字段区全宽；摘要仍和其他值对齐。拖动分隔条、展开详情或恢复图表时，已打开的内容和别名筛选结果不变。真实 `ping3` 在 844 × 390 触屏窗口最窄分栏下，`__task_pid_nr_ns` 的枚举展开区从 158 px 扩到 254 px，内容高度从 52 px 降到 26 px，原始值不变。实测记录见 `build/benchmarks/20261120-btf-side-pane/ping3.jsonl`；73 个同值别名的分页另有浏览器回归。

原型和同值候选列表在首次展开时才生成 DOM，同一次详情内反复开合不重复生成。
同一次调用切换开销口径时，只更新耗时、自耗时、调用栈行的耗时和子调用预览。原型、枚举、原始记录及源码不重建，在途源码请求不中断。筛选若保留选中调用，也不重绘与筛选无关的详情。切换调用时不会把上一次调用的候选或原始值带过去。
展开原型后，声明上方显示来源和 **Copy declaration**，不用滚到长声明末尾。按钮只复制 C 声明，保留原始缩进和换行，不附带来源说明；剪贴板不可用时可手动选中复制。
复制原型或全部候选名后，若结果提示被详情窗底部遮住、按钮仍聚焦且可见，只滚动详情窗露出提示，保留按钮焦点。不移动页面或图表；若已移走焦点或滚离按钮，迟到的结果不会把阅读位置拉回去。
直接展开时，如果声明或原始证据首行被详情窗底部遮住，只滚动详情窗；空间允许时同时露出开关与首行，原型的复制按钮也保持可见。已经可见则不滚动，页面、图表位置与键盘焦点不变。枚举、原始参数、返回记录和参数来源说明都使用同一行为，不影响别名筛选和翻页。
在触屏设备上，函数标题和原型的收起入口至少 44px 高，枚举的开关占满值列；也可用 Enter 或空格操作。桌面保留紧凑高度。
原始参数、返回记录和参数来源说明的开关也在触屏上占满值列，高度至少 44px。640px 及以下，展开的记录使用字段区全宽，自动换行但不改动原始字符。
候选数在摘要中显示。展开后先显示最多 8 个候选；9–24 个可用 **Show all N names** 直接展开。超过 24 个用 **Browse all N names** 每页浏览 24 个，保持 BTF 原始顺序，不创建嵌套滚动区。**Filter alias names** 按不区分大小写的普通子串查找所有候选，不限于当前页；点 **Clear** 或在筛选框中按 Esc 清空，回到完整列表的第一页，焦点留在筛选框。触屏上的 **Clear** 至少为 44 × 44 CSS 像素。**Copy all names** 始终复制全部候选，每行一个，不受当前页或过滤条件影响。原始数值始终可见于展开正文。640px 及以下，正文使用详情字段区全宽，摘要仍在值列；宽屏不改变列布局。浏览器回归覆盖 320px 窄屏，验证顺序、键盘切换、边界焦点、完整复制和无横向溢出。

有多页时，候选列表末尾也提供 **Previous** 和 **Next**。从页尾翻页只滚动详情窗，焦点落在新页的第一项；矮横屏下会避开固定的页面标签栏。从页首翻页时，只要能同时看见翻页按钮和新页首项，就保留在翻页按钮上，便于连续翻页；空间不足时直接聚焦新页首项。翻页不改变筛选条件或 Timeline 视野。只有一页匹配结果时不显示页尾按钮。

点 **Browse all N names** 后，如果筛选框被详情窗底部遮住，只滚动详情窗，空间不足时优先露出筛选框。键盘打开可直接输入，点按打开不唤起软键盘。结果紧跟筛选框和匹配数，不隔着翻页或复制按钮。输入时只在反馈有变化且需要时滚动详情窗，保留输入焦点，空间允许时显示首条结果。按 Enter 可定位到首条匹配；没有匹配时焦点留在输入框。

修改筛选时，候选内容没有变化就保留当前页的行；状态文字没有变化也不重复更新。用 32,769 个合成别名在 320px 触屏视口、4 倍 CPU 降速的 Chromium 上做 11 组交错对照，输入前六个共同前缀时，新增行从 144 降到 0，状态更新从 6 次降到 1 次。13 次输入的处理耗时中位数从 24.3 ms 降到 18.1 ms，每次的结果和状态文字均相同。此测量不包含浏览器绘制。记录见 `build/benchmarks/enum-filter-reuse.m7S6dY/paired.json`。

筛选结果和读屏状态立即更新，只把用于滚动定位的布局测量合并到下一帧。若焦点已经离开输入框、列表已收起或视图已切换，则不再为旧输入滚动；翻页和定位记录标签也会取消待处理的筛选滚动。
用同一份 32,769 别名测试报告，在 844 × 390 触屏视口、4 倍 CPU 降速的 Chromium 上做 9 组交错对照。9 次改写在同一任务内到达时，布局次数中位数从 9 降到 1，输入处理总耗时从 43.9 ms 降到 23.7 ms；分帧输入时，输入处理总耗时从 51.6 ms 降到 32.0 ms，但布局次数不变，没有测得绘制更快。记录见 `build/benchmarks/btf-value-layout/filter-feedback-timing/patched-ab.jsonl`。

同一别名组的后续筛选复用首次扫描生成的小写索引，显示、定位和复制仍使用 BTF 原名。只缓存一组，上限为 65,536 项和 1,048,576 个 UTF-16 代码单元；超限时照常逐项匹配，不截断结果。另一组 32,769 别名、同样视口和降速条件下的 10 组交错对照中，13 次输入（包括追加、改写、回退和清空）的处理耗时中位数从 35.45 ms 降到 28.25 ms；首次输入从 4.35 ms 增到 5.90 ms，后续输入合计从 31.05 ms 降到 21.85 ms。页内容和状态均一致，未计入绘制。记录见 `build/benchmarks/enum-filter-folded/combined-paired.json`。

候选列表会在摘要所用的名字旁标出依据：**Recorded label** 表示采集标签通过了该枚举类型和值的校验；**BTF first match** 表示缺少可靠的消歧证据，只用 BTF 首项作代表。标记跟随对应名字，不改变列表顺序、筛选或复制结果；当前页不包含该名字时，不把标记转给其他候选。

折叠摘要也区分两种依据：有已验证的标签时显示 **N names** 和 **Recorded label**；使用 BTF 首项时显示 **first of N names**。标签不匹配或找不到对应枚举值时仍有明确提示。窄详情窗优先在完整数值和标签之间换行；长枚举名继续换行显示，不截断。320px 触屏和 844 × 390 最窄横屏分栏验证了完整显示 64 位数值和标签，以及触屏筛选与翻页；同一份 `ping3` 的 `__task_pid_nr_ns` 仍显示 `PIDTYPE_PID (0)`，原始记录保留 `0 [PIDTYPE_PID]`。

候选超过 8 项且有经过校验的采集标签时，**Locate recorded label** 可直接展开列表或打开目标所在页，将焦点移到该候选，只滚动详情窗。分页列表只渲染目标页，仍保持 BTF 顺序。筛选排除了标签时会提示修改或清空筛选，不会自动更改筛选，也不会跳到未筛选的结果。如果提示被遮住，只滚动详情窗来显示它；焦点留在原按钮，提示已可见时不会再次滚动。

用同一份包含 32,769 个合成别名的 BTF 报告做 5 轮交错对照（Chromium 145，320px 触屏视口）：点击后挂载的别名行从 32,769 降到 24，点击至第二次动画帧回调的中位耗时从 550.2 ms 降到 19.2 ms。此测量只比较列表展示，不包含生成报告、遍历所有页或写入剪贴板的时间。

参数区按记录顺序展示。相邻普通参数尽量共用一行，在参数之间自动换行；枚举保留独立的展开行，不把候选挤到旁边。打开原始参数记录仍可查看完整文本或 uftrace 槽位。320px 的六参数混合样本由六行缩为三行，单文件 ftrace、分片 ftrace 和 uftrace 均保留原值及键盘展开。

## 同值异名的决策顺序

| 可用证据 | 主行 | 展开内容 |
| --- | --- | --- |
| ftrace 记录了 `mode=1 [TX_LOW_LATENCY]`，标签属于该参数 BTF 类型中值 `1` 的候选 | `TX_LOW_LATENCY (1)` · Recorded label | 原始数值与标签；有同值异名时仍按 BTF 顺序展示全部候选，不把记录标签当成调用点写法 |
| 同一枚举类型恰有一个匹配 | `TX_FAST (1)` | 枚举类型、位宽、有符号性和原始位 |
| 有多个匹配，且同构建的精确调用点能证明该参数写的是别名之一 | `TX_LOW_LATENCY (1)` · 调用点写法 | 全部别名、选中原因及调用点位置；标明这是源码写法，不是 trace 额外记录的信息 |
| 有多个匹配，且有独立证据证明执行的返回表达式使用某个别名 | `TX_RETRY (1)` · 返回路径证据 | 全部别名、选中原因及证据位置 |
| 有多个匹配，无证据或证据冲突 | `TX_FAST (1)` · 同值 2 名 | 先按该 BTF 类型内的条目顺序展示首项，其余名称全列出，注明首项仅是默认代表 |
| 类型可信，值未定义 | `7` · BTF 无对应枚举项 | 枚举类型、数值和原始位；不自动拆成按位 OR |
| 类型、采集位宽或所属模块无法核实 | 保留已有数值或原始记录 | 如需解释，注明缺少匹配 BTF、类型冲突或采集截断；不猜名字 |

BTF 只提供类型和同值候选，不能从一个数值还原程序员用过的拼写。ftrace 的标签若不属于规范化数值的候选，摘要显示 **Label mismatch**，按数值展示 BTF 首项或仅展示数值；展开能看到未经修改的标签。函数名、参数名、调用者名、附近出现的常量、调用者的 `if (ret == NAME)`，都不是消歧证据。函数上下文先用于定位对应构建、模块、原型和参数槽；只有直接调用及实参位置可靠匹配、能无歧义识别枚举项且数值一致，才把主行切换为源码写法。宏展开、内联映射或候选证据不明确时回退。返回值通常没有上述证据：普通函数进出 trace 不证明执行了哪条 `return`。

Timeline 悬停提示与详情使用同一套 BTF 匹配规则。比如 `TX_FAST (1) · first of 2 names` 表示使用 BTF 顺序中的首项，不代表实际写法；可校验的采集标签会显示 **Recorded label**。提示只显示短摘要，不加载别名列表。参数过长时优先保留放得下的完整枚举字段，用 `…` 标明省略；极长记录仍回退到原始参数的截短预览。选择切片可查看完整候选和原始记录。

## 原型与数据可信度

- 从匹配的 `BTF_KIND_FUNC` / `BTF_KIND_FUNC_PROTO` 渲染 C 风格原型，保留可验证的 typedef、限定符、返回/参数类型、参数名以及可变参数；不补写存储类、缺失的参数名或源码修饰。它是「BTF 还原」，不是源文件原样复制。
- 精确符号优先。编译器克隆只有通过现有 ABI 校验，才可引用原函数声明，并标明「原函数原型 · 已验证 ABI」；不把原型冒充为克隆的源声明。旧报告、无 BTF、同名冲突和用户态没有可信完整类型时，不用 `slotN` 或猜出的 `int` 拼原型。用户态只在独立且可信的类型来源可用时显示，不套用内核 BTF。
- 以报告构建、类型所属 BTF 对象及解析后的类型 ID 标识枚举。split BTF 的 base 与模块类型不可混合；符号同名、标量宽度相同不代表原型或枚举相同。
- 分别处理 `ENUM` / `ENUM64` 与有符号性。按可信类型位宽规范化后匹配；用十进制字符串传递 64 位值，浏览器按需用 `BigInt`，不经 JavaScript `Number`。已确认的负枚举不是 errno。展示名不进入数值比较、排序或已有数值字段，避免换名引入行为差异。

多页列表底部也显示当前范围，如 `25–48 / 73`；筛选后，分母为匹配的候选数。从底部翻页时，焦点落到新页第一项，详情窗会让出吸顶标签栏，不滚动整页。顶部的状态栏负责读屏播报，底部不重复播报。

## 实施顺序与验收

第一阶段已接入 Timeline：解析、唯一匹配、记录标签校验、首项加别名列表和折叠原型。入口在 `fglib/btf.py`、`fglib/timeline.py`；Timeline 类型和值的读取在 `assets/timeline/model.js`，详情渲染在 `assets/timeline/panels.js`。每份报告仅序列化已出现函数的原型及它们引用的枚举；每个类型只建立一次值索引，不为每次调用复制候选列表。既有报告和采集格式不变，符号名不改变 Text 或 CSV 表示。ftrace 只解释能唯一对应到原型的具名参数，支持 `参数名=数值` 和 `参数名=数值 [标签]`，不从自由格式文本推断参数位置。带逗号的引号字符串或嵌套表达式不干扰其他参数的匹配；trace 中重复出现的参数名保持原样。

如果同一个内核符号（含模块）没有参数或返回值记录，只保留原型，不生成对应字段的枚举表。参数和返回值分别判断；同名用户态调用不参与。用本机 BTF 构造 89 个引用大枚举、但未采集参数和返回值的调用后，BTF JSON 从 48,625 降到 14,363 字节，仍保留全部 89 个原型。这是针对未采集值的体积验证，不代表所有报告的体积变化。

构建函数索引时，同一个 BTF 对象内的函数签名、参数和返回类型通过有界缓存复用。缓存只在索引阶段使用，不跨 BTF 对象复用，split BTF 仍用当前对象的指针宽度。以本机 63,733 个函数的内核 BTF 做 10 次交错对照，内存中 BTF 数据的解析中位耗时从 447.1 ms 降到 245.3 ms；解析完成后的 `tracemalloc` 活跃分配从 72,092,894 字节降到 48,525,721 字节。全量函数的详情 JSON 逐字节一致；这不是整份报告的耗时或进程内存指标。

生成 Timeline 时，每个内核函数身份（模块和符号）只保留一份参数、返回值的采集状态，按首次出现顺序输出；同名用户态调用不参与。以 100 万条、覆盖 66,150 个内核函数身份的合成混合录制做 9 次交错对照，这一步的中位耗时从 185.1 ms 降到 107.1 ms，`tracemalloc` 峰值分配从 48.3 MB 降到 12.6 MB。测试机三份真实录制的 Timeline JSON 逐字节一致。

构建详情数据时，相同 BTF 对象中的同一原型可复用已排版的参数列表，再分别写入函数名；只有枚举字段需要查枚举类型。缓存有界且只在单次构建中有效。本机 63,733 个函数的全量投影中，9 次交错对照的中位耗时从 575.4 ms 降到 442.1 ms，`tracemalloc` 峰值分配从 31.3 MB 降到 27.8 MB；详情 JSON 逐字节一致。该结果不包含读取 BTF 和生成 HTML 的耗时。

详情投影会先按 ELF 批量提交缺少精确原型的克隆候选，避免对同一个 ELF 重复读取符号表和 DWARF。单个 DWARF 编译单元读取失败时，跳过受影响的候选，不影响其他编译单元；只有通过 ABI 校验才展示克隆的原型。以同一份 `ping3.txt`、同一内核和 `fgreport --fast` 生成离线 Windowed Text 报告，端到端耗时从 90.13 秒降到 51.45 秒（单次同机对照），峰值 RSS 基本不变。两版均有 82,529 条记录和 58,539 个切片；浏览器解码后的 BTF 详情、Timeline 列及字符串表、嵌入源码分别有相同的 SHA-256。Chromium 实测第 1001 行 `make_vfsuid` 的原型默认折叠、展开后与数据一致；双向返回分别恢复 Timeline 选中切片及缩放范围、Text 横纵滚动位置，不修改浏览器历史。生成和验证记录见 `build/benchmarks/20261120-generation-profile/`。

ftrace 末尾的 `...` 保留在界面上，此前已记录的枚举仍可显示名字。对于 Linux 7.0 `print_function_args()` 使用的 `mode=(ENUM64)[0x…]` 格式，仅在 BTF 确认该参数为 `ENUM64` 且单字足以承载值时解析；多字和截断记录（如 `(ENUM64)[0x25:...]`）不猜测拼接结果。展开仍可看到原始括号、进制和省略号。

第二阶段尚未接入：使用同一展示接口接入可复核的调用点证据，先支持位置和实参明确的直接调用。没有可靠返回路径证据时不做返回别名推断。回归见 `tests/test_btf_detail.py`；现有 clone ABI 与无 BTF 回退用例继续适用。

可行性验证：用 GCC 11.4.0 和 Clang 20.1.8 将同一行上的 `submit(TX_FAST) + submit(TX_LOW_LATENCY)` 编译为 `-O2 -g -gdwarf-5`。两者都记录了不同的返回 PC 和相同的调用目标，但实参记录未区分拼写：GCC 两处都是寄存器值表达式，Clang 两处都是常量 `1`。这个样本中 Clang 的行表附带源文件 MD5，GCC 的未附带。即使有返回 PC，也不能用 DWARF 的数值表达式或单一源行挑别名；需要能验证到具体实参的源码级证据。
