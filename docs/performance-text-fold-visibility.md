# Text 折叠范围复用 / Fold-range masks（2026-11-13）

优化**显式启用的实验性 Windowed Text** 的无筛选折叠状态。不改变默认完整
renderer、自动分流阈值、版本、Timeline 外观或记录内容。报告重新生成后，无需
新增参数：在 Text 工具中选择 **Windowed Text**，或在 HTTP URL 后加 `?text=windowed`。
用法及整篇文档操作限制见[窗口化说明](performance-text-window.md)。

## 问题与实现

本文保留折叠范围阶段的基线和数字。后续重建改用完整二进制掩码批量更新导航，
缓存和临时输入各增加每行 1 字节，见[导航优化](performance-text-navigation-visibility.md)。
导航掩码按显示位置对齐，不能与本文按原始 ordinal 对齐的折叠掩码混用。

前一阶段已经[复用原始记录 ordinal](performance-text-geometry.md)，但 37 万行
稀疏折叠仍约有 400ms 同步阻塞。当前版本 CPU profile 显示，重复祖先字符串虽已
按次缓存，众多不同祖先链仍重复遍历相同前缀；完全未隐藏的记录也读取折叠字段。
Profile 仅用于定位，不能用来计算正式加速比。

- 复用 `prepareFolding` 已有的成员范围，不新增持久的父子索引。每个严格 true 的
  标志按现有范围批量置位临时 `Uint8Array`；不假定范围连续或调用只发生在单一任务。
- 成员范围包含自身 entry。只在置位范围内修正 entry：自身折叠且没有折叠祖先时
  保持可见；折叠祖先仍会隐藏它。重复 entry、祖先包含自身、缺失父项和交错任务
  都按旧逐行 reference 判断，不只依赖 `blocks.entry` 的最后一个入口。
- JS 属性键 `null` 同时覆盖空 own-ID 和字面同名 ID；空串及特殊 ID 不丢失。
  掩码按原始 ordinal 访问，不把稀疏/超大行号或排序位置当作数组下标。
- **有筛选时保留原按次 predicate**，只对匹配记录读取折叠元数据，不为很少的命中
  额外展开全量范围。空 Set 仍表示没有命中，与 null 的“没有筛选”不同。
- 每次重新生成掩码，原地修改同一个折叠对象也不复用旧状态；无匹配启用范围时
  返回 null，不分配掩码或访问记录的折叠字段。

完整可见原始行号、导航顺序及计数不变；源码/参数/调用结构和完整绘制块校验不变。
160 单元挂载上限、网络分组/LRU、512 行解析单位、取消、旧窗口保留/重试和 Full Text
fallback 没有更改。默认完整 DOM renderer 继续使用既有 reference 路径。

## 成本与边界

存在匹配的启用范围时，每次额外分配 `N` 字节：本轮 72,176 / 371,997 行分别约
**70.5 / 363.3 KiB**。没有跨操作掩码缓存，不要求立即 GC；调用方自行保留旧数组
也会延长其存活。既有 task/duration ordinal、模型、范围索引及网络暂存另计。

重叠范围可能重复写入；范围准备后仍扫描字节掩码，之后可见序列/导航仍遍历完整
模型。不会把同步任务自动拆为多帧，也不承诺任意深度/百万行输入或浏览器均流畅。
过滤命中非常多时仍有原 predicate 的成本；后续还需处理协作重建和分散 DOM 解析。

## 回归与复现

新增模型回归直接逐项对比 `hiddenMask` 和旧 `visible`：嵌套/缺失/重复祖先、重复
entry、交错范围、特殊及空 ID、严格 true、空模型、稀疏大行号、同对象状态变更，
另对 601 行随机范围元数据执行 40 组严格布尔/非布尔状态的 reference 对比，
以及未置位记录不得访问折叠元数据。600 层共享祖先的非 entry 隐藏不再逐链判断。
浏览器继续对比 90 组顺序/耗时方向/折叠/筛选的完整结果，并检查无筛选使用掩码、
有筛选不构建掩码。现有源码、取消、错误重试、Full Text 和挂载预算回归继续运行。

```bash
python3 funcgraph.py TRACE --no-config --timeline --enable-fold --filter \
  --func-links --report-mode sidecar --output REPORT_DIRECTORY
```
